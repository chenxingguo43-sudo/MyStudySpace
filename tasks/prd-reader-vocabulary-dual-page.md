# PRD: Reader + Vocabulary 双页化

## 1. 概述

项目从“番茄钟 + 俄语知识库 + 统计 + 生词本”的多功能学习舱，收缩为一个围绕俄语 B2 学习的双页应用：

- `reader.html` 是默认首页，承担书架、阅读、习题、错题、划词查询和生词收藏。
- `vocabulary.html` 是配套页面，承担生词管理、上下文复习和从生词返回原文。

旧 `index.html`、番茄钟、俄语知识库和相关统计页面不再进入主流程。它们在验证无依赖后移入 `legacy/`，作为历史备份保留，不直接删除。

本次采用最小稳定方案：保留 Reader 与 Vocabulary 当前视觉设计，只统一入口、双向导航和数据边界，不进行整体 UI 重做。

## 2. 已确认决策

- 访问 `/` 时直接进入 `reader.html`。
- 旧功能移入 `legacy/`，保留备份。
- Reader 与 Vocabulary 在同一浏览器标签页中直接切换，不使用 iframe。
- 第一阶段不重做整体视觉，只增加克制、统一的双页导航。
- 现有阅读进度、生词记录、错题记录和词典数据必须保留。

## 3. 当前问题

1. 当前根入口 `index.html` 仍是旧调度中心，会加载番茄钟、俄语知识库、统计页和生词页 iframe，与现在的使用目标不一致。
2. Reader 只在章节总结中提供“去背单词”链接，Vocabulary 只在部分来源记录中返回 Reader，双向切换入口不稳定。
3. `vocabulary.html` 仍读取 `pomodoro-custom-bgs`，说明生词页还残留对番茄钟命名和数据的依赖。
4. 旧页面、测试产物和当前核心页面混在项目根目录，后续维护时容易误改、误测或误提交。
5. `reader.html` 当前还有一批未提交的面包屑导航改动，必须先独立验证和保存，不能与双页化混成一个提交。

## 4. 目标

- 用户打开 `http://localhost:3000/` 后一步进入 Reader。
- Reader 和 Vocabulary 之间最多一次点击完成切换。
- iPad 竖屏、iPad 横屏和桌面端均使用同一套直接导航，不弹出多余标签页。
- 页面切换前保存当前阅读位置；返回 Reader 后恢复上次阅读位置。
- Reader 收藏的生词在 Vocabulary 中可见，现有复习进度不丢失。
- 主流程不再请求或渲染番茄钟、旧俄语知识库和旧统计页。
- 旧功能可从 `legacy/` 找回，但不影响核心应用。
- 为核心双页提供独立、不会重建教材数据的测试命令。

## 6. 交互设计

### 6.1 双页切换控件

两个页面复用同一种紧凑分段控件：

- `阅读器`：书本图标 + 文本。
- `生词本`：书签/卡片图标 + 文本。
- 当前页面显示明确选中状态，并设置 `aria-current="page"`。
- 桌面端放入现有顶部操作区，不增加第二条大型导航栏。
- iPad 和手机端保持至少 44 x 44 px 的点击区域。
- 不使用 iframe，不打开新标签页，不使用装饰性动画。

### 6.2 Reader -> Vocabulary

用户点击“生词本”时：

1. Reader 先调用现有阅读位置保存逻辑。
2. 当前标签页导航到 `vocabulary.html`。
3. Vocabulary 默认恢复用户上次使用的筛选或复习状态；若无有效状态则显示生词列表。

章节总结中的“去背单词”链接改为同标签页跳转，并与顶部入口使用同一导航函数。

### 6.3 Vocabulary -> Reader

- 点击顶部“阅读器”时进入 `reader.html`，Reader 使用现有最近阅读记录恢复位置。
- 点击某个生词的“返回原文”时，继续使用已有 `reader.html?book=...` 深链接，并定位到来源章节。
- 来源信息不完整时退回 Reader 书架，不制造错误章节编号。

### 6.4 根入口

- Node 静态服务器访问 `/` 时直接提供 `reader.html`。
- 新 `index.html` 只承担静态部署兼容：立即跳转到 `reader.html`，并提供无 JavaScript 时可点击的“进入阅读器”链接。
- 新 `index.html` 不加载 iframe、番茄钟、俄语知识库或统计脚本。

## 8. 功能需求

- FR-1：服务器必须把 `/` 映射到 Reader，而不是旧调度中心。
- FR-2：静态 `index.html` 必须兼容没有 Node 路由的部署并进入 Reader。
- FR-3：Reader 和 Vocabulary 必须提供一致的双页切换控件。
- FR-4：双页切换必须使用当前标签页。
- FR-5：Reader 离开前必须保存最近阅读状态。
- FR-6：Vocabulary 返回来源时必须保留已有 `book/chapter` 深链接语义。
- FR-7：共享生词键继续使用 `vocabulary-review-records`。
- FR-8：阅读错题键和其他 Reader 进度键不得因入口调整而改名。
- FR-9：Vocabulary 必须从番茄钟背景键解耦。
- FR-10：旧页面不得被 Reader 或 Vocabulary 主流程加载。
- FR-11：旧页面归档前必须完成依赖搜索和恢复说明。
- FR-12：任何移动或归档不得包含真实凭据文件。
- FR-13：核心测试不得重写教材 JSON 或留下 Playwright 截图日志。
- FR-14：所有 UI 改动必须在桌面、iPad 竖屏、iPad 横屏和手机宽度验证。

## 9. 非目标

- 不重做 Reader 或 Vocabulary 的整体视觉风格。
- 不引入 React、Vue、构建系统或新的前端框架。
- 不创建新的 iframe 应用外壳。
- 不重写生词复习算法、词态引擎或错题分类逻辑。
- 不清洗 OCR 教材内容。
- 不修复 P1 `Q003/Q006/Q009` 原书答案台账；该问题单独处理。
- 不迁移或清空用户 localStorage。
- 不自动 push 到远程仓库。
- 不删除旧功能代码；第一阶段只归档。

## 10. 视觉与可用性要求

- 复用两个页面现有颜色、字体、主题和按钮语言。
- 双页切换使用分段控件语义，不增加卡片或大面积装饰区。
- 当前页面选中态不仅依靠颜色，还应有字重、底色或边框差异。
- 图标仅辅助识别，按钮必须保留“阅读器”“生词本”文本。
- 控件尺寸稳定，切换选中态时不得导致顶部布局位移。
- 长标题、窄屏和系统大字体下不得与现有导航重叠。
- 保持 Reader 的沉浸阅读优先级，双页控件不能抢占正文视觉焦点。

## 11. 技术设计

### 11.1 文件级改动

| 文件 | 计划改动 |
|---|---|
| `reader.html` | 增加双页切换控件；离开前保存阅读状态；统一“去背单词”跳转 |
| `vocabulary.html` | 增加双页切换控件；保留来源深链接；迁移并移除番茄钟背景依赖 |
| `server.js` | 将 `/` 映射到 `/reader.html`；保留 Reader/Vocabulary 当前 API |
| `index.html` | 替换为轻量 Reader 跳转页；旧内容先移入 `legacy/` |
| `legacy/` | 保存旧调度中心及停用页面，增加恢复说明 |
| `package.json` | 增加非破坏性的 `test:reader-vocab` 命令 |
| `tests/` | 增加入口、双向导航、数据保持和无旧页面加载测试 |

### 11.2 数据兼容

以下键保持原名和原结构：

- `vocabulary-review-records`
- `rr_b2_reading_progress_v1`
- Reader 现有最近阅读、书签、完成状态和错题记录键

Vocabulary 背景使用新键，例如 `vocabulary-custom-bgs-v1`。若新键为空且旧 `pomodoro-custom-bgs` 有合法值，则只复制一次；之后不再依赖旧键。

### 11.3 路由策略

- `/`：Reader。
- `/reader.html`：Reader 的稳定直接地址。
- `/vocabulary.html`：Vocabulary 的稳定直接地址。
- `/reader.html?book=...&chapter=...`：继续作为来源返回地址。
- `/legacy/`：历史功能，不进入主导航。

### 11.4 安全约束

- `cloudsync-config.js` 含真实令牌，任何阶段均不得暂存或提交。
- 编辑 `package.json` 时保持无认证仓库 URL。
- 归档移动使用明确文件清单，不使用针对项目根目录的递归删除。
- 每次提交前检查 `git diff --cached --name-only`。

## 14. 风险与回退

### 风险 1：移动旧文件破坏隐藏依赖

缓解：归档放在最后，先用 `rg` 和浏览器网络记录确认依赖；每批移动使用独立提交。

回退：撤销归档提交即可恢复旧位置，不触碰 Reader/Vocabulary 数据。

### 风险 2：页面切换丢失阅读位置

缓解：统一从 Reader 导航函数调用保存逻辑；测试书籍、章节和题目定位。

回退：保留直接 URL 和现有最近阅读键，不改变数据格式。

### 风险 3：背景键迁移影响 Vocabulary 外观

缓解：只复制合法旧值，不删除旧键；新键无效时回退默认主题。

回退：恢复旧读取逻辑即可，旧数据仍然存在。

### 风险 4：完整测试重建教材并污染工作区

缓解：建立专用非破坏性命令；完整 B2 测试仅在明确需要时运行，并在运行前记录状态。

### 风险 5：双页导航挤压 iPad 工具栏

缓解：复用现有操作区、稳定尺寸、四档视口检查，不新增第二条大型导航。
