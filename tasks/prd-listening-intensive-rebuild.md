# PRD: В мире людей 听力精听批量重建

## 1. Introduction / Overview

本项目重建 `В мире людей — 听力口语` 中已有正确配套媒体的 35 个单元，使其全部达到可发布的逐句精听标准。重建在隔离的 staging 区完成，35 个单元全部通过数据、内容和浏览器验收后，再一次性发布到 Reader。

当前 Reader 中“媒体已核验”只代表媒体文件和教材版本对应，不代表逐句时间轴、中文译文或题目依据已经完成。重建需要把以下四类信息绑定成一个可追溯整体：

1. 原始配套媒体及媒体哈希。
2. 教材俄文原文、题目、答案和页码。
3. 每个实际播出句段的时间范围与中文译文。
4. 每道题支持答案的一个或多个可播放句段。

本轮不处理缺少正确媒体的 28 个 ТРКИ-3 单元。它们继续保持 `source-mismatch` / `unavailable`，不得使用 TTS、旧错误 MP3 或其他朗读版本替代。

## 2. Confirmed Decisions

| 决策 | 结果 |
|---|---|
| 本轮范围 | 35 个已有正确媒体的单元 |
| 质量标准 | 原书核对 + 音频对齐 + 自动校验；仅冲突项交给俄语母语者 |
| 发布方式 | 35 个单元完成后一次性发布；28 个 ТРКИ-3 后续单独处理 |
| 缺失媒体政策 | 保持不可用，禁止 TTS 和无关录音替代 |
| 学习者职责 | 学习者不承担俄语原文或音频准确性复核 |

## 4. Goals

- 将 35 个单元全部转换为可审计、可定位、可翻译的逐句精听单元。
- 对当前 109 个未解决句段逐一判定：对齐失败、分段错误、合法省略或媒体不一致。
- 为所有最终显示的可播放句段提供中文译文。
- 对 175 道题逐题建立依据，支持一题一条或多条音频依据。
- 对不在当前媒体中的题目明确标记，并从当前音频的作答分母中排除。
- 只把机器和教材无法消解的冲突交给俄语母语者。
- 在 35 个单元全部通过门禁后执行一次原子发布。
- 保证重新运行转换脚本不会覆盖已核验的译文、题目依据和覆盖状态。

## 5. Non-Goals

- 不为 28 个缺少正确媒体的 ТРКИ-3 单元制作伪精听数据。
- 不使用 TTS、旧错误 MP3、其他教材录音或网络朗读替代原版媒体。
- 不要求学习者人工判断俄语原文是否正确。
- 不把 ASR 输出当作教材原文；ASR 仅用于音频定位和冲突发现。
- 不在本轮重做听力工作台的整体视觉设计。
- 不在单元未通过全部发布门禁时提前开放正式精听入口。
- 不将 `machine-aligned`、`source-checked` 表述为“母语者完整听审通过”。

## 6. Source-of-Truth Hierarchy

发生冲突时按以下优先级处理：

1. 已确认版本的原始媒体及 SHA-256。
2. 原书俄文 аудиотекст、题目、答案键和页码。
3. 本地原书中文对照 Markdown。
4. ASR 词级或句级时间候选。
5. 俄语母语者对冲突项的裁决记录。

ASR 与原书冲突时，不得自动改写原书。必须先判断是口语省略、字幕差异、媒体摘录、教材排印问题还是 ASR 识别错误。

## 7. Target Architecture

### 7.1 Isolated rebuild workspace

正式章节数据在发布前保持稳定。重建数据进入独立目录：

```text
data/textbook/listening_speaking/rebuild/
├── manifest.json                 # 35 单元状态账本
├── units/
│   ├── ch0000.learning.json      # 单元学习层数据
│   └── ...
├── conflicts/
│   ├── ch0000.conflicts.json     # 仅保存未解决冲突
│   └── ...
└── reports/
    ├── data-validation.json
    ├── browser-validation.json
    └── release-candidate.json
```

正式的 `chXXXX.json` 继续保存媒体、题目和最终发布数据；`timelines/chXXXX.json` 保存音频覆盖与时间轴。staging 数据只有通过发布脚本后才能合并进入正式章节。

### 7.2 Stable segment identity

每个最终可播放句段必须有稳定的 `segmentId`，格式为 `chXXXX-sNNN`。题目依据引用 `segmentId`，不得只依赖数组下标。

示例：

```json
{
  "segmentId": "ch0014-s003",
  "text": "Качественный сервис...",
  "translation": "优质的服务……",
  "playlistIndex": 0,
  "startTime": 14.38,
  "endTime": 27.76,
  "timingStatus": "aligned",
  "sourceSentenceIndexes": [3, 4]
}
```

### 7.3 Question evidence contract

每道题必须属于下列两种状态之一：

```json
{
  "status": "playable",
  "segmentIds": ["ch0014-s003", "ch0014-s004"],
  "quote": "...",
  "translation": "...",
  "reasoning": "服务、停车和片源共同支持选项 А。",
  "pages": [39, 40]
}
```

或：

```json
{
  "status": "not-in-bound-media",
  "sourceQuote": "...",
  "translation": "...",
  "reasoning": "题目依据位于教材原文未被当前媒体收录的部分。",
  "pages": [41, 43]
}
```

`not-in-bound-media` 题目必须在 UI 中禁用，并从当前媒体作答总数和计分中排除。

### 7.4 Unit state machine

每个单元只能按以下顺序前进：

```text
inventory_locked
  -> media_verified
  -> coverage_resolved
  -> timeline_complete
  -> translation_complete
  -> evidence_complete
  -> conflicts_resolved
  -> data_validated
  -> browser_validated
  -> release_ready
  -> published
```

状态只能由校验脚本推进，不允许人工直接把单元标记为 `release_ready`。

## 8. Production Workflow

| 阶段 | 输入 | 操作 | 输出 | 完成门槛 |
|---|---|---|---|---|
| P0 基线冻结 | 当前35单元、媒体、原书 | 记录哈希与当前统计 | `manifest.json` | 35个单元均有固定输入指纹 |
| P1 媒体复核 | 原始MOV/MP4 | 核对版本、时长、播放列表和电影边界 | 媒体审计记录 | 每个媒体与教材单元唯一对应 |
| P2 原文重建 | 原书Markdown和答案键 | 固定俄文原文、题目、选项、答案和页码 | 教材基准层 | 与原书逐项一致 |
| P3 覆盖判定 | 媒体、原文、ASR | 判断完整、摘录或不匹配 | coverage元数据 | 每个源句都有“播出/省略”结论 |
| P4 时间轴重建 | ASR候选、教材原文 | 对齐、合并短叹词、修复边界 | 最终句段 | 所有显示句段均有单调时间范围 |
| P5 中文切分 | 原书中文对照、最终句段 | 按最终音频句段重切中文 | 逐句译文 | 每个显示句段译文非空 |
| P6 题目溯源 | 题目答案、最终句段 | 绑定一条或多条依据并写明推理 | evidence数据 | 175题全部被分类 |
| P7 冲突裁决 | 自动发现的冲突 | 机器复查；仍不确定则提交母语者 | 冲突裁决记录 | `pending`冲突为0 |
| P8 数据验收 | staging单元 | 执行结构、来源、计分和时间校验 | 数据验收报告 | 35/35通过 |
| P9 浏览器验收 | release candidate | 桌面、移动端和压力测试 | 浏览器验收报告 | 35/35通过关键流程 |
| P10 原子发布 | 通过验收的35单元 | 备份、合并、构建、回归 | 正式章节数据 | 发布后全套测试通过 |
| P11 回滚演练 | 发布前备份 | 验证可恢复到发布前状态 | 回滚记录 | 恢复过程无数据丢失 |

## 9. Parallel Execution Design

### 9.1 Ownership rules

- 一个单元在同一时间只能由一个内容 worker 持有。
- worker 只写自己的 `rebuild/units/chXXXX.learning.json` 和冲突文件。
- 时间轴 worker、翻译 worker和题目依据 worker不得同时修改同一单元。
- coordinator 负责分配、合并、运行门禁和处理失败重试。
- 正式 `chXXXX.json` 只由发布脚本写入。

### 9.2 Internal waves

虽然最终一次性发布35个单元，内部生产分三波：

#### Wave A: 19个完整时间轴单元

这些单元不应重新转写，只补译文、题目依据和来源记录：

`ch0000`–`ch0005`、`ch0007`、`ch0008`、`ch0011`–`ch0013`、`ch0017`、`ch0025`、`ch0026`、`ch0030`–`ch0034`。

工作量：246个句段、95道题。

#### Wave B1: 8个短缺口部分时间轴单元

优先处理只缺1至3句的单元：

- `ch0006`：2/3句已定时。
- `ch0009`：3/4句已定时。
- `ch0010`：8/9句已定时。
- `ch0016`：29/31句已定时。
- `ch0018`：14/17句已定时。
- `ch0027`：27/29句已定时。
- `ch0028`：35/36句已定时。
- `ch0029`：34/35句已定时。

先判断缺句是音频未播出还是对齐失败，再进入译文和题目依据阶段。

#### Wave B2: 6个复杂电影单元

- `ch0019`：27/40句已定时。
- `ch0020`：24/57句已定时。
- `ch0021`：20/32句已定时。
- `ch0022`：36/56句已定时。
- `ch0023`：18/30句已定时。
- `ch0024`：24/31句已定时。

这些单元必须先做媒体覆盖审计，禁止把整本教材原文强制塞进电影摘录。

#### Regression set

`ch0014`、`ch0015` 作为黄金模板，不重新生产内容，只用于验证新管线没有破坏已完成数据。

### 9.3 Concurrency limit

- 同时最多处理4个内容单元。
- 同时最多运行1个CPU ASR任务，避免当前机器长时间满载和输出互相污染。
- 母语者冲突包按批次提交，每项包含音频切片、原书原文、ASR候选和明确问题。

## 10. User Stories

### US-001: 建立重建状态账本

**Description:** 作为项目协调者，我需要看到35个单元的真实状态，使未完成内容不能被误判为完成。

**Acceptance Criteria:**
- [ ] `manifest.json`列出35个单元及输入哈希。
- [ ] 每个单元只有一个合法状态。
- [ ] 状态变更包含时间、执行者类型和校验结果。
- [ ] 缺失文件或非法跳级会使校验失败。

### US-002: 隔离重建成果

**Description:** 作为开发者，我需要在不污染正式Reader数据的情况下并行重建单元。

**Acceptance Criteria:**
- [ ] staging数据与正式章节分离。
- [ ] 内容worker不能直接写正式章节。
- [ ] 可根据staging数据生成预览章节。
- [ ] 未通过单元不会出现在发布候选中。

**Acceptance Criteria:**

- [ ] 俄文、题目和答案均可追溯到原书页码。

### US-004: 完成19个现有完整时间轴单元

**Description:** 作为学习者，我需要完整时间轴单元具备逐句中文和题目依据。

**Acceptance Criteria:**
- [ ] 246个现有可播放句段均有中文译文。
- [ ] 95道题全部具有可播放依据或明确的未覆盖状态。

- [ ] 不重新生成或降低现有可靠时间轴质量。

### US-005: 解决14个部分时间轴单元

**Description:** 作为学习者，我需要每个显示句段都能准确定位，且音频未包含的原文不会伪装成可播放句子。

### US-006: 生成逐句中文学习支持

**Description:** 作为学习者，我需要每个实际播放句段旁边直接看到中文意思。

**Acceptance Criteria:**
- [ ] 每个最终显示句段都有非空中文译文。
- [ ] 译文按最终句段切分，不使用整段中文错误错位。
- [ ] 译文来源文件和状态被记录。
- [ ] 重新运行转换脚本不会删除译文。
- [ ] 在浏览器中验证桌面和移动端显示。

### US-007: 建立175道题的听力依据

**Description:** 作为学习者，我需要知道每道题为什么选择A、B或C，并能播放对应原句。

**Acceptance Criteria:**

- [ ] `playable`题目至少引用一个有效`segmentId`。

- [ ] 每条依据显示俄文、中文和定位播放按钮。
- [ ] `not-in-bound-media`题目不参与当前媒体计分。

### US-008: 建立冲突复核队列

**Description:** 作为质量负责人，我需要只把无法自动解决的俄语冲突交给母语者。

### US-010: 完成浏览器与压力验收

**Description:** 作为学习者，我需要在连续操作和播放推进时保持页面稳定。

### US-011: 原子发布35个单元

## 11. Functional Requirements

- FR-1: 系统必须维护35单元的重建状态账本和输入哈希。
- FR-2: 重建过程必须在staging目录完成，正式章节不得被内容worker直接修改。
- FR-3: 每个最终显示句段必须具有稳定`segmentId`、俄文、中文、开始时间和结束时间。
- FR-4: 每个媒体或播放列表项必须记录来源和SHA-256。
- FR-5: 系统必须区分完整媒体、合法摘录和来源不匹配媒体。
- FR-6: 合法摘录必须记录教材原文覆盖范围和省略范围。
- FR-7: 每道题必须具有`playable`或`not-in-bound-media`证据状态。
- FR-8: `playable`证据必须引用一个或多个存在的`segmentId`。
- FR-9: `not-in-bound-media`题目必须禁用并排除计分。
- FR-10: 所有最终显示句段必须具有非空中文译文。
- FR-11: 转换脚本必须保留已核验译文、证据、覆盖和裁决记录。
- FR-12: 未解决冲突必须进入结构化队列，禁止以备注文本代替状态。
- FR-13: 只有冲突项需要母语者复核，学习者不参与内容核验。
- FR-14: 数据校验失败时发布命令必须终止且不得部分写入。
- FR-15: 35个单元必须作为一个发布批次原子上线。
- FR-16: 发布前必须生成可恢复备份并验证回滚流程。
- FR-17: 28个无正确媒体单元必须保持不可播放。
- FR-18: ASR结果只能作为对齐证据，不能自动替换教材俄文。
- FR-19: 一题多依据必须在UI中分别显示并可独立播放。
- FR-20: 自动播放不得强制滚动学习页面。

## 12. Automated Validation Gates

### Gate A: Media

- 媒体文件存在且哈希与manifest一致。
- 单文件和五段新闻播放列表映射正确。
- 电影正片时间轴不越过片尾练习边界。

### Gate B: Timeline

- 每个显示句段`endTime > startTime >= 0`。
- 同一播放列表内开始时间单调。
- 除允许的边界容差外不得重叠。
- 发布数据中不存在`unmatched`显示句段。
- 摘录省略范围与显示句段不矛盾。

### Gate C: Translation

- 每个显示句段都有非空中文。
- 中文来源文件存在。
- 译文数量与最终显示句段数量一致。

### Gate D: Question evidence

- 175道题全部分类。
- 可播放依据引用存在的句段。
- 引用媒体、播放列表和时间范围一致。
- 不可播放题目不进入分母。
- 正确答案仍与原书答案键一致。

### Gate E: Conflict

- `pending`冲突数必须为0。
- 母语者裁决项保留原问题和最终结论。
- 不得用删除冲突记录的方式通过门禁。

### Gate F: Browser

- 35单元均能进入考试、精听和复盘模式。
- 逐句播放、题目依据、中文和进度正常。
- 连点压力、播放滚动、桌面和移动端全部通过。

## 13. Release Procedure

1. 冻结35个单元的staging内容。
2. 运行全部数据门禁并生成`release-candidate.json`。
3. 确认35个单元均为`release_ready`，冲突为0。
4. 生成发布前备份，记录路径和文件哈希。
5. 运行发布脚本，将staging学习层合并到正式章节。
6. 运行Node测试、媒体验收、Reader静态检查和浏览器测试。
7. 对模板单元`ch0014`、`ch0015`执行回归对比。
8. 对随机抽取及高风险单元执行人工浏览器冒烟。
9. 生成最终重建报告，区分机器校验、原书核对和母语者冲突裁决。
10. 验证回滚命令可以恢复发布前备份，再宣布发布完成。

## 15. Failure and Recovery Policy

- 单个单元失败只退回该单元，不撤销其他staging成果。
- 时间轴失败退回`coverage_resolved`，不得继续制作题目依据。
- 译文或证据失败退回对应阶段，不重新运行已通过的媒体步骤。
- 母语者仍无法判定的冲突保持`pending`并阻止整批发布。
- 发布过程中任一步失败，停止后续写入并使用备份恢复。
- 禁止使用`git reset --hard`或覆盖用户现有未提交修改进行恢复。

## 16. Risks and Mitigations

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 电影媒体是摘录而非完整原文 | 伪造句子时间轴 | 先做coverage判定，再做对齐 |
| 多worker修改同一文件 | 数据覆盖 | 单元锁和单一owner |
| ASR误识别俄语 | 错误原文或边界 | 原书为文本权威，ASR只用于定位 |
| 中文按原段落而非音频句段切分 | 译文错位 | 时间轴定稿后再切译文 |
| 一道题依赖多句 | 依据不完整 | 支持多个`segmentId` |
| 转换脚本覆盖人工成果 | 大量返工 | staging学习层和保留性合并 |
| 母语者复核范围失控 | 成本不可控 | 仅提交结构化冲突项 |
| 一次性发布风险高 | 全模块回归 | staging、原子发布、备份和回滚演练 |
| 旧媒体报告被误读为内容完成 | 错误发布 | 新建独立的精听重建验收报告 |
