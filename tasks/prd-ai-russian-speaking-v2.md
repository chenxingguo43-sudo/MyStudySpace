# PRD: AI 俄语口语陪练 V2

> 状态：产品决策已收束，尚未开始实现  
> 日期：2026-07-27  
> 目标用户：当前仅服务应用所有者本人  
> 前置版本：V1 Reader + Vocabulary 离线双页应用

## 1. 概述

V2 在 V1 的 Reader 与 Vocabulary 基础上增加一套 AI 俄语口语陪练。它首先解决的不是“得到一个漂亮的口语分数”，而是让目前主动口语约 A2/B1、平时极少开口的学习者，在每天约十分钟内持续说俄语，并逐渐具备与真实俄语使用者进行自然交流的能力。

产品采用语音消息式交互，不在首个 V2 版本中追求全双工 Live。用户按住说话、松开发送；系统完成中俄混合转写，AI 返回俄语语音和同步字幕。轻微错误不打断交流，重要纠错集中在会话结束后的复盘。

V2 同时提供两类口语训练：

- **日常对话**：自由开口优先，AI 像懂中文的俄语朋友或耐心外教。
- **B2 练习**：基于教材任务与独立题库，分为引导练习和模拟考试。

V2 仍是私人学习工具。多用户、商业化、社交、排行榜和订阅系统不进入当前范围。

## 2. 版本边界

### 2.1 V1 保持不变

- Reader 与 Vocabulary 是离线可用的核心。
- 《В мире людей — 语法词汇》使用固定、可追溯的基础解析。
- V1 不接入 GPT、Groq、语音聊天、在线评分、后端账户或云端记忆。
- V2 不得破坏 V1 的教材数据、阅读进度、生词、错题、录音或导入导出能力。

### 2.2 V2 新增

- AI 日常语音对话。
- B2 引导练习与模拟考试。
- 中俄混合语音转写。
- AI 俄语语音、同步字幕和建议回复。
- 会话复盘、重说、表达激活与历史会话。
- 可查看、可过期、可删除的学习记忆。
- 私人后端和可替换的 ASR、对话模型、TTS、复盘服务。
- Android App 外壳及移动端原生录音体验。

### 2.3 后续版本预留但不实现

- 实时摄像头对话。
- 完整视频理解。
- 全双工 Realtime、打断、回声消除和连续音频流。
- 自由发言的音素级、音节级和重音精细评分。
- 任意自定义 Agent 提示词。
- 面向公众的账号、付费、配额、内容审核和运营后台。

## 3. 已确认的产品原则

1. **开口优先**：十分钟是否成功，首先看用户是否持续说俄语，而不是错误数量。
2. **流畅与准确分时处理**：会话中流畅优先，结束后准确性优先。
3. **当前产品只有一个 Agent**：导师、规划、记忆和学习画像能力都归属于白夜俄语 Agent；Reader 只是可替换客户端，不作为嵌套 Agent 或生产依赖。
4. **Phase 0 技术决策先于供应商绑定**：ASR 与 TTS 已完成当前 MVP 的实测选型；LLM 供应商、输出 schema、提示词骨架和上下文策略仍待独立能力测试，不在本次决策中提前拍板。
5. **不假装精确**：普通 ASR 不能支撑音素、重音和流利度的精确打分时，不展示伪科学分数。
6. **不强迫逐轮确认**：转写默认直接用于交流；编辑保留，但仅在需要时使用。
7. **不靠上下文编造**：影响意思的内容没听清时，系统必须询问，不能静默猜测。
8. **中文是支架**：允许用户用中文求助或设定场景，但 AI 应尽快把对话带回俄语。
9. **支架逐级展开**：先自由回答，再给关键词、句型框架、完整建议，成功后逐渐撤掉支架。
10. **重复不等于掌握**：表达只有在新场景中独立使用后，才算激活或掌握。
11. **记忆必须可治理**：记忆要有来源、时间、置信度和有效期，用户可以查看、修改、固定、归档或删除。
12. **离线不丢数据**：AI 功能需要联网，但网络或供应商故障不得导致录音和消息丢失。
13. **同一能力，多处入口**：Reader 章节口语任务和口语模块共用一套训练引擎，不复制实现。
14. **先为一个人做深**：优先满足所有者的真实习惯，不提前增加大众产品复杂度。

## 4. 目标

- 用户从口语模块首页一次点击即可开始日常俄语对话。
- 用户可以用中文、俄语或中俄混合语音提出话题、角色和场景要求。
- 日常练习中用户说话时间高于 AI，目标占比不低于 60%。
- AI 通常用一到两句俄语加一个问题推动用户继续说。
- 系统能可靠保存原始录音、原始转写、确认表达和自然表达四类证据。
- 每轮结束后只展示 1–3 个真正有价值的问题，不强行凑数。
- 用户可以重说最弱句，并比较原始录音与改进录音。
- 会话表达能够在后续对话中被重新引出，而不是只进入一个很少打开的列表。
- B2 引导练习允许逐级支架，模拟考试保持无提示和统一复盘。
- 所有 AI 供应商可以在不修改核心界面的情况下替换。

## 5. 成功定义

### 5.1 一次日常会话成功

- 用户完成至少一轮有效语音往返。
- 系统保存用户实际说话时长和语音条数。
- 用户无需逐条编辑转写即可完成会话。
- 会话结束后可以看到重点复盘、完整记录和重说入口。

“今天成功练习”不要求表达已达到 B2，也不要求零语法错误。

### 5.2 一个表达掌握

表达状态按以下证据推进：

```text
刚遇到
-> 借助完整建议说出
-> 只看关键词说出
-> 在新问题中主动使用
-> 已激活 / 已掌握
```

仅跟读一次不得标记为掌握。

### 5.3 B2 一题练习成功

- 用户覆盖任务要求中的核心要点。
- 系统保存第一次回答、转写、评分证据和改进目标。
- 用户能查看考试维度反馈和一个明确的下一步行动。
- 引导练习可完成分段训练或完整回答；模拟考试不得在过程中提供提示。

## 6. 信息架构

V2 App 使用五个底部入口：

```text
首页 | Reader | Vocabulary | 口语 | 我的
```

V1 可以隐藏“口语”；V2 启用后显示完整五项。

### 6.1 首页

- 继续阅读。
- 今日单词。
- 开始十分钟俄语。
- 待重说数量。
- 最近学习记录。

### 6.2 口语首页

```text
[开始十分钟自由对话]

继续上次的话题
待重说
今日会话表达复现

B2 口语
- 引导练习
- 模拟考试
- 最近练习

最近会话
```

口语首页不使用必须选择的场景宫格。场景仅作为“不知道聊什么”时的可选建议。

### 6.3 我的

- 学习档案：当前水平、目标、教材、每日目标。
- AI 陪练：默认身份、声音、语速、提示强度。
- 记忆管理：查看、修改、固定、过期、归档、删除。
- 数据与存储：录音占用、清理规则、导出、恢复。
- 服务状态：ASR、对话模型、TTS、复盘服务状态和最近延迟。
- 权限与隐私：麦克风、照片、视频权限和全部数据删除。

用户自设水平与系统估计口语表现必须分开保存和显示。

## 7. 日常对话体验

### 7.1 一键开始

- 点击主入口后直接进入对话，不先展示人设或场景配置页。
- 默认使用上次的日常陪练身份；首次使用默认为“俄语朋友”。
- AI 用一句简短俄语开场，例如 `Привет! О чём поговорим сегодня?`。
- 用户可以直接用中文、俄语或混合语言回答。

### 7.2 自由场景与中文导演指令

用户可以随时说：

- “我们模拟一下在咖啡馆点餐，你当服务员。”
- “我想聊聊看电影。”
- “我今天不知道聊什么，你问我简单一点的问题。”
- “这个词用俄语怎么说？”
- “我们换一个话题。”

AI 可以用一句短中文确认设置或解释词语，然后立即回到俄语。场景不是预先锁死的内容类型。

### 7.3 陪练身份

- **俄语朋友**：自然、简短、温和追问，除听不懂外尽量不暂停。
- **耐心外教**：可以每十分钟暂停 1–2 次，带用户重说一个高价值表达，然后立即回到话题。
- **B2 考官**：仅用于 B2 模式，考试过程中不提供学习支架。

V2 不开放任意自定义提示词。身份只改变关系、语气和允许的教学行为，不能覆盖核心安全、记忆和纠错规则。

### 7.4 说话长度

- AI 大多数轮次使用一到两句俄语并提出一个问题。
- AI 可以偶尔讲三到四句，使交流保持自然。
- 如果 AI 连续两轮明显比用户说得长，下一轮必须缩短。
- 统计只计算用户自己的录音时长，不把 AI 播放时长计入练习时长。

## 8. 微信式录音交互

### 8.1 日常模式

底部输入栏提供键盘/语音切换。语音模式使用按住说话：

```text
按住并在中心松开 -> 发送语音
拖入左上并松开   -> 取消并删除本次录音
拖入右上并松开   -> 转写到可编辑文字草稿，不自动发送
```

- 手指进入不同区域时，对应区域高亮，并触发一次轻微震动。
- 手指滑回中心时恢复“松开发送”。
- 录音中显示时长和稳定尺寸的音频状态动画。
- 正常松开后语音立即成为消息气泡，不出现强制预览页。
- 用户可以撤回刚发送的录音并重录。
- 第一次切换到语音模式时应提前完成麦克风权限申请，避免权限弹窗打断长按手势。

### 8.2 B2 模式

B2 回答可能持续数分钟，不使用持续按住。采用点击开始、点击结束的长录音方式，并显示计时。以后可以增加录音锁定，但不得把日常短消息和 B2 长回答强行统一为一种手势。

### 8.3 可复用候选

- 录音底层候选：`capacitor-voice-recorder`，负责 Android/iOS/Web 权限与文件录制。
- 手势和动效参考：`3llomi/RecordView`。
- 不因一个录音组件引入 Vue，也不直接依赖 2015–2018 年无人维护的仿微信工程。
- 最终技术选型必须通过 Android 真机权限、后台切换、来电打断和音频文件完整性测试。

## 9. 中俄混合转写

### 9.1 单一转写入口

正常语音发送和“右上滑转文字”必须调用同一套转写服务：

```text
audio
-> transcribeMixedAudio(audio, primaryLanguage="ru", allowedLanguages=["ru", "zh"])
-> rawTranscript
```

区别仅在结果去向：

- 正常发送：保留音频，转写用于 AI 对话和会话记录。
- 右上转文字：转写进入可编辑草稿，不自动发送。

### 9.2 转写规则

- 当前 MVP 采用 Groq `whisper-large-v3` 双通道转写：同一条音频分别以 `language=zh` 和 `language=ru` 请求两次。
- 两个通道均使用 `verbose_json`，保留原始文本、分段和时间戳；两份结果同时交给白夜俄语 Agent，由 Agent 结合上下文选择、融合或追问。
- 日常模式不得把语言强制锁为俄语；双通道是识别策略，不是把用户语言翻译成一种语言。
- 使用“转写”而不是“翻译”任务；必须保留中文与俄语原文。
- B2 模式以俄语为主，但仍保留中文求助片段。
- 保存原始录音、两路原始转写和用户确认/编辑后的转写；可对可疑片段重试。
- 后处理只允许修复标点和明确的 ASR 机械错误，不能凭上下文补造内容词。
- 已完成的 20 条中俄混合基准结果表明：`whisper-large-v3` 优于 `whisper-large-v3-turbo`；双通道能改善俄语专有名词和完整俄语句子的保留，但仍需 Agent 判断，不能用脆弱的固定规则强行拼接。
- Groq 请求需通过当前代理；批量请求需限速（约 300ms+ 间隔）并重试空转写。

### 9.3 没听清时

1. AI 诚实请求用户重说。
2. 连续两到三次仍无法理解时，显示“你想表达什么？”并允许文字输入。
3. 用户通过文字确认意图后，系统保存该确认，但不把识别失败直接标记为发音错误。
4. 可理解度只记录：一次听懂、重说后听懂、通过文字确认。

### 9.4 发布前语料测试

必须用用户本人声音建立至少 20 条中俄混合测试样本，覆盖：

- 中文开头、俄语结尾。
- 俄语开头、中文结尾。
- 一句话切换两次以上。
- 大段俄语中只夹一个中文词。
- 发音不准的俄语加中文求助。
- 人名、地名、教材词汇和外来词。

## 10. AI 回复、语音与字幕

### 10.1 发送后的状态顺序

```text
松开发送
-> 用户语音气泡立即出现
-> 显示转写/理解状态
-> AI 开始生成回复
-> 第一段语音就绪后开始自动播放
-> 字幕随语音同步显示
-> 播放结束后显示建议关键词
```

- 不等待完整长回复全部合成后才开始播放。
- 字幕不得在语音播放前完整泄露整段内容。
- AI 语音默认自动播放，可随时暂停和重播。
- 提供 `0.8x` 与 `1x` 重播速度。
- 俄语朋友与耐心外教默认使用用户选定的稳定声音；B2 考官可使用中性声音。
- 当前 MVP 的俄语 TTS 主方案为本地 Silero `v5_ru`，默认音色为 `aidar`：用户试听后认为语速较慢、发音清晰。
- 保留 5 个可自由切换的 Silero 音色：`aidar`、`baya`、`kseniya`、`eugene`、`xenia`。声音选择必须是配置项，不得写死在 UI 或业务逻辑中。
- Silero 首次加载需要初始化，后续本地 CPU 合成速度很快；生产接入需采用分段合成/播放，先播第一段，不等待完整长回复。
- 当前 Silero 模型许可为个人 MVP 可用范围；商业化前必须重新核验模型许可，不能默认视为 unrestricted commercial use。
- 在线 Edge TTS 保留为可替换备选/故障路径；TTS 供应商失败时先显示文字，允许重试或切换其他 provider。
- 不添加背景音乐。

### 10.2 建议回复

播放结束后默认只显示关键词：

```text
关键词：кино | выходные | с друзьями
```

用户可以依次展开：

1. 句型框架。
2. 完整俄语建议。
3. 中文翻译。
4. 参考音频。

完整建议不得自动发送；用户必须自己说出来。系统记录本轮使用了哪一级支架。

### 10.3 自适应支架

- 第一次回答很短：提出一个容易展开的追问。
- 第二次仍很短或明确卡住：给关键词或句型框架。
- 第三次仍无法表达：给完整建议。
- 借助建议成功后：撤掉一层帮助，换一个相近问题测试迁移。
- 简短但语义完整的回答不能只因字数短而被强迫扩展。

## 11. 纠错策略

### 11.1 会话中

- 小语法错误但意思明确：不打断；AI 可以在后续回复中自然复述正确形式。
- 表达不自然但意思明确：继续交流，留到复盘。
- 关键内容无法理解：请求重说。
- 耐心外教每十分钟最多主动暂停 1–2 次，只选择重复出现、明显影响理解或特别值得掌握的问题。

一次外教暂停必须短：

```text
先回应用户表达的内容
-> 指出这一句值得重说
-> 给关键词或正确句子
-> 用户重说一次
-> 立即回到原话题
```

### 11.2 会话后

- 每次展示最多三处重点，不强行凑够三条。
- 优先级依次为：影响理解、明显高频问题、自然表达升级、值得迁移的表达。
- 普通日常会话不展示音素、重音或流利度的伪精确分数。

## 12. 会话结束与复盘

### 12.1 结束方式

- 用户可以随时主动结束。
- 十分钟到时，AI 先提示“最后一个问题”。
- 用户回答后，AI 简短回应并进入复盘，不在最后追加长篇教学语音。

### 12.2 复盘首页

顶部显示可验证事实：

- 用户说话总时长。
- 发送语音条数。
- 使用提示次数。
- 请求重说次数。

随后展示 1–3 处重点。单条重点可以包含：

- 原始录音。
- 原始转写。
- 用户确认表达。
- 更自然的表达。
- 为什么值得修改。

### 12.3 收尾重说

- 系统选出最值得重说的一句。
- 用户可以播放原始录音、AI 参考读音并查看支架。
- 用户重新录制后，原始与改进录音并排保留。
- 不强制用户当场完成；退出后首页显示“待重说”。
- 完成后只报告可验证状态，例如“完整识别”“主要意思可理解”“仍有片段没听清”。

### 12.4 完整对话

完整记录位于重点复盘之后，提供：

- 全部对话。
- 只看我说的。
- 只看修改处。

点击用户消息可以查看原始录音、原始转写、确认表达和自然表达。

## 13. 会话表达

会话表达与普通 Vocabulary 队列分开。Vocabulary 可以提供“会话表达”标签页，但真正的复习发生在后续口语对话中。

每条表达至少保存：

- 俄语表达及可选重音标记。
- 中文意义。
- 来源会话和用户原句。
- 自然版本。
- 原始与改进录音引用。
- 支架等级。
- 当前激活状态。
- 最近练习和下次复现时间。

下一次会话只主动安排 1–2 个旧表达，AI 通过自然问题引出。用户在新场景中主动说出后，表达才进入“已激活”。

## 14. 历史会话

历史按日期显示简洁摘要：

```text
7 月 27 日 · 和俄语朋友聊看电影
6 分 42 秒 · 14 条语音 · 2 个表达

[继续这个话题] [重新练薄弱句]
```

- “继续这个话题”创建新会话，并带入旧会话摘要，不覆盖旧记录。
- “重新练薄弱句”只生成针对旧问题的练习。
- 历史详情可以重新打开完整复盘。
- 最近会话有轻量连续性，但 AI 不得每次开场强行翻旧话题。
- 用户提出新话题或“换个话题”后，旧话题立即退到后台。

## 15. 记忆系统

### 15.1 记忆类型

| 类型 | 示例 | 保存规则 |
|---|---|---|
| 稳定资料 | 家乡、母语、长期目标 | 用户确认后长期保留 |
| 当前状态 | 年级、口语水平、当前教材 | 带更新时间，定期确认 |
| 学习证据 | 常见错误、已激活表达 | 可自动更新，必须可查看 |
| 临时偏好 | 当前 UI 喜好、近期兴趣 | 默认 30 或 90 天过期 |

### 15.2 记忆字段

每条记忆必须包含：

```text
id
category
content
source
createdAt
lastConfirmedAt
confidence
expiresAt
status
```

### 15.3 行为规则

- 学习错误和表达证据可以自动保存。
- 家乡、学校、生活经历等个人事实必须经过一次确认。
- 临时偏好自动过期。
- 新信息与旧信息冲突时优先使用较新的已确认信息，旧信息进入历史。
- 每次复盘显示“本次记住了什么”。
- 用户可以查看、修改、固定、归档和删除所有记忆。
- “大一”等随时间变化的信息不得作为永久静态事实反复使用。
- API 模型本身的对话上下文不能被当作应用记忆；应用必须管理自己的显式记忆存储。

## 16. B2 口语

### 16.1 任务来源

- Reader 中《В мире людей — 写作口语》的章节口语任务。
- Reader 中现有 `speaking-practice` B2 任务。
- 独立 B2 真题或题库。

Reader 点击“开始口语练习”时，必须把任务、章节、相关词汇和表达传入同一 B2 引擎。用户也可以从口语首页浏览教材任务或独立题库。

### 16.2 引导练习

```text
阅读任务
-> 查看必须覆盖的要点
-> 自由准备，可用中文求助
-> 分段训练或完整回答
-> 仅确认没听清的转写片段
-> 查看维度反馈与下一目标
-> 查看优化答案
-> 可重新回答
```

- 准备时间默认不限。
- 第一次回答前只显示任务要点。
- 关键词和句型需要点击展开。
- 完整参考答案必须在第一次回答后才能显示。
- 分段训练支持“观点、原因、例子、结尾”等结构。
- 分段之间 AI 可以指导；完整回答录制过程中不得打断。
- 用户可以逐渐从“先回答核心问题”升级到完整 B2 结构。

### 16.3 模拟考试

```text
抽题
-> 严格准备计时
-> 严格回答计时
-> 过程中无提示、无纠错、无中文支架
-> 完成规定任务后统一评分与复盘
```

- 正式计时和评分权重必须依据可追溯的 TRKI-2 官方规则校准。
- 没有完成官方规则核验前，不得把临时估算包装成官方考试标准。

### 16.4 B2 反馈

在不超出可验证能力的前提下覆盖：

- 任务完成度。
- 结构与连贯性。
- 词汇范围和适切性。
- 语法准确性。
- 交流可理解度。

结果同时显示：

- 考试维度分数或等级。
- 支持评分的具体证据。
- 下一次最需要完成的一个目标。

普通自由回答不进行音素级评分。已知目标文本的跟读或朗读模式可以在后续版本中增加对齐、漏词、节奏和重音训练。

## 17. 服务架构

### 17.1 可替换接口

```text
transcribe(audio, context) -> transcript result
reply(conversation, memory, policy) -> streamed text
synthesize(text, voice) -> streamed or chunked audio
review(session, rubric) -> evidence-based review
```

- ASR 当前决策为 Groq `whisper-large-v3` 双通道方案；详细结果见 `data/asr-results-groq-dual-v2.json`。
- LLM 仍未完成供应商抉择：候选与调用方式必须通过固定测试集比较质量、约束遵循、结构化输出、延迟、Token、成本和资源占用后再决定。
- LLM 接口必须接收两路 ASR 原始结果和上下文，并支持流式文本；不得把某个供应商的私有响应格式泄漏到 UI/业务层。
- TTS 当前决策为本地 Silero `v5_ru`，默认 `aidar`，保留 5 音色自由切换；Edge TTS 作为可替换备选。
- UI 和业务逻辑不得依赖单一供应商的私有响应格式。

### 17.2 客户端与私人后端

Android 客户端负责：

- 录音与播放。
- 触摸手势和页面状态。
- 本地会话、记忆、复盘和录音索引。
- 离线草稿与失败重试队列。

私人后端负责：

- 保存供应商 API Key。
- 调用 ASR、对话模型、TTS 和复盘服务。
- 统一请求格式、超时、重试、额度与错误映射。
- 防止客户端直接暴露上游凭据。

任何 GPT、Groq 或中转站密钥都不得写入 HTML、JavaScript、APK、Git 仓库或可导出的学习数据。

### 17.3 失败状态

- 转写失败：保留原始录音，允许稍后重试。
- 对话模型失败：保留用户消息并显示“等待回复”。
- TTS 失败：先显示文字，允许稍后重新生成或使用本地 TTS。
- 网络断开：允许继续录音并保存草稿，恢复后再发送。
- 重复提交：服务端和客户端使用消息 ID 保证同一语音不会生成两条重复消息。

  "reason": "string",
  "retryStatus": "pending|complete|skipped",
  "retryAudioRef": null

### 18.2 录音保留

- 普通完整会话录音默认保留 30 天。
- 被选为重点、已经重录或手动收藏的录音长期保留。
- 清理前必须保留文字记录、复盘、表达状态和必要元数据。
- 用户可以查看空间占用、提前清理或固定录音。
- 清理任务不得删除仍被重点复盘或表达记录引用的音频。

### 18.3 导入导出

- V2 数据导出不得包含 API Key。
- 录音和文本可以分开导出，避免普通备份体积过大。
- 导入时按稳定 ID 合并，不静默覆盖较新的本地记录。
- V1 Reader/Vocabulary 数据与 V2 口语数据保持独立版本号。

**描述：** 作为移动端用户，我希望网络或供应商失败时保留刚才说的话，从而不必重新录制。

- [ ] ASR 失败后原始音频仍可播放和重试。
- [ ] 对话模型失败后消息保留为等待状态。
- [ ] TTS 失败后文字仍显示。
- [ ] 断网录音进入本地待发送队列。
- [ ] 重试不会创建重复消息。

### US-021: 管理录音空间
**描述：** 作为长期用户，我希望普通录音自动清理、重要录音长期保留，从而控制手机空间。

**验收标准：**
- [ ] 普通录音默认 30 天后可清理。
- [ ] 重点、重录和收藏录音不会自动删除。
- [ ] 个人中心显示录音空间占用。
- [ ] 删除前检查是否仍被复盘或表达引用。

### US-022: 查看服务状态而不暴露密钥
**描述：** 作为应用所有者，我希望知道 ASR、GPT 和 TTS 是否可用，从而排查问题而不把密钥放进 App。

**验收标准：**
- [ ] 个人中心显示服务可用性和最近错误。
- [ ] 客户端日志和导出数据不包含上游密钥。
- [ ] APK、静态资源和 Git 仓库中不存在上游密钥。
- [ ] 私人后端使用独立密钥存储。

## 20. 功能需求

- **FR-1:** V2 必须保留 Reader 与 Vocabulary 的现有离线能力和数据格式。
- **FR-2:** 口语首页必须提供一次点击开始日常对话的主入口。
- **FR-3:** 日常对话不得要求先选择场景。
- **FR-4:** 用户必须可以用中文、俄语或中俄混合语言控制话题。
- **FR-5:** AI 默认使用俄语，中文只用于指令确认、词语解释和脱困。
- **FR-6:** 日常录音必须支持中心发送、左上取消、右上转文字。
- **FR-7:** 右上转文字必须生成可编辑草稿且不自动发送。
- **FR-8:** 正常发送和转文字必须共用同一 ASR 接口。
- **FR-9:** ASR 必须执行转写而不是翻译，并保留语言切换。
- **FR-10:** 所有用户语音必须先保存本地引用，再开始依赖网络的处理。
- **FR-11:** AI 无法确定关键内容时必须请求重说。
- **FR-12:** 连续失败后必须提供文字确认入口。
- **FR-13:** 系统不得把 ASR 失败直接归因于用户发音。
- **FR-14:** AI 回复应在第一段 TTS 就绪后开始播放。
- **FR-15:** 字幕必须与语音同步，不在播放前完整展示。
- **FR-16:** 建议回复默认只显示关键词。
- **FR-17:** 完整建议和中文翻译必须分别展开。
- **FR-18:** 系统必须保存每轮使用的支架等级。
- **FR-19:** 日常会话中小错误不得触发阻断式纠错。
- **FR-20:** 耐心外教每十分钟最多主动暂停两次。
- **FR-21:** AI 必须控制回复长度，目标使用户说话时间占比不低于 60%。
- **FR-22:** 十分钟到时必须先完成最后一个问题再结束。
- **FR-23:** 复盘必须显示用户真实说话时长、语音数、提示数和重说数。
- **FR-24:** 每次复盘最多显示三处重点。
- **FR-25:** 完整会话必须支持全部、只看用户、只看修改筛选。
- **FR-26:** 最弱句必须可以保存原始和改进两版录音。
- **FR-27:** 未完成重说不得阻止退出，但必须进入待重说列表。
- **FR-28:** 会话表达必须与普通单词复习队列分开。
- **FR-29:** 表达必须在新场景独立使用后才可标记已激活。
- **FR-30:** 历史会话必须同时提供继续话题和重新练习。
- **FR-31:** 继续话题必须创建新会话，不覆盖历史。
- **FR-32:** 个人事实记忆必须经过用户确认。
- **FR-33:** 临时偏好必须具有过期时间。
- **FR-34:** 用户必须能查看、编辑、固定、归档和删除记忆。
- **FR-35:** B2 必须区分引导练习和模拟考试。
- **FR-36:** B2 长回答使用点击开始和点击结束，不要求持续按住。
- **FR-37:** 引导练习第一次回答前不得展示完整参考答案。
- **FR-38:** 引导练习必须同时支持分段和完整回答。
- **FR-39:** 模拟考试过程中不得提供提示、中文支架或纠错。
- **FR-40:** B2 反馈必须提供维度结果、证据和一个下一目标。
- **FR-41:** 未核验的 B2 计时与权重不得标记为官方标准。
- **FR-42:** Reader 章节任务必须通过稳定任务 ID 接入同一 B2 引擎。
- **FR-43:** 供应商调用必须经过可替换服务接口。
- **FR-44:** 上游 API Key 不得进入客户端、APK、Git 或学习数据导出。
- **FR-45:** 网络和供应商故障不得删除未完成录音。
- **FR-46:** 在线 TTS 失败时必须保留文字，并允许本地 TTS 兜底。
- **FR-47:** 普通录音默认保留 30 天，重点录音长期保留。
- **FR-48:** 音频清理必须检查引用完整性。
- **FR-49:** V2 数据导入导出不得修改 V1 Reader/Vocabulary 数据。
- **FR-50:** 照片和视频附件类型可以预留数据枚举，但 V2 首版不得依赖其实现。

## 21. 设计要求

- 这是学习工具，不制作营销落地页。
- 首页和口语页应安静、清晰、适合重复操作，不使用大量装饰卡片。
- 底部录音控件必须有稳定尺寸，手势状态变化不得推动聊天列表布局。
- 所有关键触控区域至少 44 x 44 px，并处理 Android 底部安全区。
- 录音取消、转文字和发送三个状态除颜色外还要使用图标、文字和位置区分。
- 重点复盘先于完整记录，但不得把完整记录隐藏到不可发现的位置。
- 字幕、俄语正文和中文翻译具有清晰层级；中文翻译默认收起。
- 页面不得用说明性大段文字占据第一屏。
- 视觉风格在单独设计阶段确定，本 PRD 不绑定液态玻璃或任何会过期的临时审美偏好。

## 22. 技术考虑

### 22.1 现有可复用能力

- `reader.html` 已有 `MediaRecorder` 与 IndexedDB 本地录音。
- `renderSpeakingPractice` 已支持 B2 任务、提纲、录音和回听。
- `renderWritingSpeakingChapter` 已展示《В мире людей — 写作口语》的章节口语任务。
- `b2-exam.html` 已有 TRKI-B2 题型模板，但不能直接视为已完成的官方评分引擎。
- V2 应复用任务 ID、教材来源和已有录音迁移能力，而不是复制题库。

### 22.2 推荐演进路线

1. 先在 Web 结构中建立供应商无关的数据和服务契约。
2. 用真实 Android 设备完成录音、权限、文件和手势技术试验。
3. 决定使用 Capacitor 包装当前 Web 应用，还是为口语模块使用更原生的 Android 层。
4. 无论包装方案如何，保持会话数据和后端接口一致。

### 22.3 性能与状态

- 录音开始和手势反馈不得等待网络。
- 发送后 300 ms 内应出现本地消息气泡或明确状态。
- 长音频优先传文件引用或流，不在客户端长期复制大体积 Base64。
- 页面切后台、锁屏、系统回收和权限撤销必须有明确恢复策略。
- 会话、消息和上传使用稳定 ID，支持幂等重试。

## 23. 非目标

- 不在 V2 首版实现全双工实时通话。
- 不做持续监听、VAD 自动抢话、打断或回声消除。
- 不从普通自由语音生成音素、音节、重音和流利度精确分数。
- 不把所有错误在会话中逐条弹出。
- 不要求用户逐轮确认或编辑转写。
- 不把会话表达直接混入普通单词背诵队列。
- 不把预置场景做成用户唯一能聊的内容。
- 不开放任意 Agent 系统提示词编辑。
- 不依赖 ChatGPT 账户记忆代替应用记忆。
- 不在客户端保存 GPT、Groq、中转站或 TTS 上游密钥。
- 不实现多人账号、社交、排行榜、订阅、广告和公开内容市场。
- 不实现照片、视频或实时摄像头对话；只预留附件契约。
- 不在本 PRD 中重做 Reader、Vocabulary 或 V1 固定解析。

## 26. 成功指标与发布门槛

- 日常对话从口语首页到可录音状态不超过一次点击。
- 20 条本人中俄混合测试语料中至少 18 条保留核心意思和语言切换。
- 正常对话不需要逐轮确认转写。
- 十分钟会话中，用户说话时长目标占比不低于 60%。
- ASR、对话模型或 TTS 任一失败时，已录用户音频丢失数量为 0。
- 每次复盘重点数量为 1–3，且每条都有原始证据。
- 待重说、表达激活和历史继续均可跨应用重启恢复。
- 录音清理不会删除仍被重点或收藏引用的音频。
- Reader、Vocabulary 现有核心测试保持通过。
- APK 和公开静态资源扫描不到任何上游 API Key。
- Android 目标设备上连续完成 10 轮语音往返，无布局重叠、手势误触或音频文件损坏。

## 27. 风险

### 风险 1：中俄混合 ASR 对短中文词不稳定

缓解：本人语料基准、保持多语言模式、可疑片段二次识别、原始音频保留、低置信时询问而非猜测。

### 风险 2：旧仿微信组件难以接入现代 Android

缓解：复用录音底层，不复用整套旧 UI；手势层使用清晰状态机自行实现；真机优先验证。

### 风险 3：AI 说得太多，反而减少用户开口

缓解：回复长度策略、用户/AI 说话时长监测、每轮一个问题、自适应缩短。

### 风险 4：记忆变旧或过度引用

缓解：分类、时间戳、过期、冲突覆盖、用户确认、可见记忆变更和手动删除。

### 风险 5：评分超出语音证据能力

缓解：普通会话只报告交流可理解度；B2 评分引用文本证据；精细发音评分留给已知文本模式。

### 风险 6：录音和历史长期占用空间

缓解：30 天自动清理、重点固定、引用检查、空间面板和文字/音频分离备份。

### 风险 7：中转站或供应商能力不完整

缓解：上线前分别测试文本流、图片能力、ASR、TTS、超时和错误格式；服务适配层不绑定单一供应商。

### 风险 8：API Key 泄露

缓解：私人后端保存上游密钥、客户端只使用应用级授权、日志脱敏、仓库与 APK 扫描、泄露凭据立即轮换。

## 28. 开放问题

以下问题不阻塞产品定义，但必须在对应实现阶段解决：

1. TRKI-2 口语模拟考试的正式准备时间、回答时间、任务组合和评分权重，需要依据官方可追溯材料核验。
2. LLM 候选（包括 DeepSeek、Groq 或其他兼容服务）是否满足文本流、结构化输出、指令遵循、错误语义和成本/延迟要求，需要独立能力测试；当前尚未选定。
3. Edge TTS 是否作为长期在线备选，以及其目标 Android 设备上的首句延迟，需要后续验证；Silero 已确定为当前 MVP 主 TTS。
4. 当前 Web 应用最终采用 Capacitor 包装，还是增加原生 Android 口语层，需要 Phase 0 技术试验决定。
5. 记忆和录音是否在未来跨设备同步，不进入 V2 首版。
6. 照片讨论和短视频抽帧讨论只预留附件类型，具体实现进入后续版本。
