# Reader × Book2Skill × MinerU 第一版审计报告

> 日期：2026-08-20
> 状态：第一版审计，供讨论与决策；本报告没有修改 Reader、Skill 或原始学习数据。
> 产品依据：[WHITE_NIGHT_AGENT_FOUNDATION.md](./WHITE_NIGHT_AGENT_FOUNDATION.md)

## 0. 先说结论

这次对照说明了一个关键事实：Reader 现在已经是一个可用的“教材练习客户端”，但还不是《在人世间》原书完整教学路径的复刻。

Reader 当前最完整地承载了：

- 俄语原文与中文学习辅助翻译；
- 阅读理解选择题/判断题；
- 原书答案、部分解释和题目来源信息；
- 本地做题记录。

原书和 Book2Skill 还明确包含，但 Reader 当前阅读模块没有完整承载的内容主要是：

- `Активизация языковых и речевых навыков`：词汇、词汇搭配、构词、句法同义转换等语言激活；
- 每篇阅读材料后的 `Говорение / беседа`，尤其是 ТРКИ-2 口语第 15 题式的输出任务；
- 原书自带的全书词汇-语法测试与相应矩阵；
- 作者关于三种阅读方式、难度梯度、任务顺序的完整教学解释。

因此，下一步不应该把 17 本 Skill 直接全部复制进 Reader，而应该建立三层分工：

```text
MinerU / 章节原文        = 原始材料与证据
Book2Skill                = 方法、目录、概念和跨书导航
Reader                    = 可执行练习、学习记录和客观证据
白夜俄语 Agent            = 讲解、诊断、迁移练习和计划建议
```

## 1. 审计范围与证据等级

### 1.1 本轮范围

本轮按 6 个 Reader 项目盘点：

1. `reading_speaking`：В мире людей — 阅读口语
2. `listening_speaking`：В мире людей — 听力口语
3. `listening_speaking_mock`：В мире людей — ТРКИ-2 模拟考试
4. `writing_speaking`：В мире людей — 写作口语
5. `zlatoust_grammar`：В мире людей — 语法词汇
6. `russian_b2`：俄语 B2 全模块

其中前 5 个是 Reader 的产品入口；`russian_b2` 是一个统一的 B2 综合项目。模拟考试和语法词汇模块在产品上是独立入口，但不应自动当作两本新的原书。

### 1.2 资料优先级

本报告采用以下证据顺序：

1. 本地 MinerU 清理后的 `章节/` 与 `原始OCR/`；
2. Reader 当前 `data/textbook/` 结构化数据；
3. Codex 已迁移的 17 个 Book2Skill；
4. 审计判断。

Skill 没有某项内容，不代表原书没有；Reader 有某项内容，也不自动代表它已经完成原书核验。

### 1.3 可信度标记

| 标记 | 含义 |
|---|---|
| `可直接使用` | 结构、答案或来源信息已经足够，适合进入学习流程 |
| `需核对` | 题面、答案、翻译、来源或 OCR 仍需回到原 PDF/页级 OCR |
| `受材料限制` | 原书矩阵、图片、音频或页面内容无法可靠恢复 |
| `AI 辅助` | 非原书原话或原书解析，必须在产品中明确标注 |

### 2.1 一个需要保留的区分

`zlatoust_grammar` 的作者是 А.И. Захарова 等，而《在人世间·阅读口语》是 Макова / Ускова 的教材。两者都训练俄语 B2 语法词汇，但不是同一本书。以后补内容时，应保留原书身份，不能因为都叫“语法词汇”就合并成一个无来源题库。

### 3.1 17 个 Skill 的边界结论

Book2Skill 的 `SKILL.md` 明确把很多书整理成“方法和索引”，例如阅读 Skill 的 Scope & Limits 写明它不包含整套练习文本和答案。这个边界是合理的，不应把 Skill 的“不含全文”误报成转换失败。

但这也带来一个产品要求：以后 Agent 需要回答具体题目时，必须同时能找到：

- Skill 中的解题方法；
- Reader 或资料库中的具体题面；
- 原书/页级来源锚点；
- 题目答案的核验状态。

## 4. 《在人世间·阅读口语》原书设计

本地资料：`俄语资料库/В мире людей 阅读口语 Markdown版/`。

### 4.1 原书层级

项目 README 记录：原书页 1–186，整理为 11 个章节文件；页 1–166 是原书内容，页 167–186 是后加的 AI 词汇附表，不应当当作原书正文。

作者的主线可以概括为：

```text
选择阅读方式
  → 阅读文本
  → 阅读理解
  → 语言/词汇/构词/句法激活
  → 口语 беседа / 输出
  → 词汇-语法测试与矩阵
```

Book2Skill 将这条路径归纳为 12 个方法章节：三种阅读方式、理解题、词汇激活、构词、句法同义转换、口语 беседа、主题/体裁、词汇-语法测试、工作/控制矩阵等。

### 4.2 原书里必须谨慎处理的页

根据项目 README 和 Source Of Truth：

- 页 52–54、95–98、155–160 的答案矩阵不可可靠恢复，属于“受材料限制”；
- 页 167–186 是 AI 生成词汇附表，不是原书阅读正文；
- 文学阅读部分需要对照 PDF/原始 OCR 保留 `needs_review` 风险。

这意味着：即使某个 Skill 说“有答案/矩阵”，Reader 也不能把受损矩阵当成确定答案写入正式题库。

### 5.1 已保留的内容

- 30 个主要阅读文本均已有 Reader 入口；
- 241 道练习均有可提交的答案字段；
- 多数单元有 `answerKeySource`、`translationSource` 或 `exerciseSource`；
- 部分题目有 `sourceAnchor`、定位句、排除项、复盘等教学辅助；
- Reader 已经能记录客观作答证据。

### 5.2 当前明显缺口

#### 缺口 A：Reader 以“理解题”为主，原书的语言激活没有成为同一学习链条

Skill 的核心框架明确写出：阅读后应进入词汇、构词、句法同义转换和词汇-语法测试。当前 `reading_speaking` 的 241 道练习主要是 `choice`，没有对应的独立 `activation`、`wordformation`、`transformation` 或 `speaking` 数据类型。

这不是说 Reader 完全没有语法能力；语法能力存在于 `zlatoust_grammar` 和 `russian_b2`。问题是：它们没有和每篇阅读文本的上下文形成可追踪的“读后激活”链条。

#### 缺口 B：每篇文本后的口语 беседа 没有完整落入阅读模块

Skill 将 `Говорение / беседа` 定义为每篇文本之后的口语输出结构，包含表达观点、同意/反驳、举例、比较和评价。当前阅读 JSON 的主要题型没有对应的口语任务对象。

这类内容适合 Reader 做成可记录的提纲/录音任务，也适合 Agent 用 Skill 讲解和追问，但不能只在对话里“泛泛地说可以练口语”。

#### 缺口 C：原书全书词汇-语法测试与 Reader 语法词汇模块没有建立来源关系

原书项目 README 记录了第 2 部分和第 3 部分的词汇-语法测试及答案；Reader 的 `zlatoust_grammar` 是另一个作者体系的 597 题训练模块。两者目前看起来是并行存在，而不是“原书读后测试 → 统一错题证据”的关系。

建议先建立来源映射，不要直接合并题目。

#### 缺口 D：来源字段的完整性不一致

- `ch0000.json` 没有顶层 `answerKeySource`、`translationSource` 或 `exerciseSource` 字段，但题目本身包含答案和解释；这属于“内容可能可用、证据链不完整”；
- `ch0011`、`ch0017` 使用 `judgement` 题型，并有 `exerciseSource`，但缺少与其他单元相同的答案/翻译来源结构；
- `ch0007`、`ch0008`、`ch0009`、`ch0018`、`ch0027` 等单元有较明确的 `exerciseSource`，适合做来源链样板；
- 不能因为题面已有中文解释，就把解释当成原书官方解析；需保留 AI 辅助或项目生成来源标签。

## 6. 深挖样板：四个代表任务组

本轮按“两个完整链条样板 + 两个差异样板”选择。

### 样板 1：1.4.2《Пересадка головы》

**为什么选它：** Reader 有 8 道理解选择题，并带有 `answerKeySource`、`translationSource`、`exerciseSource`，可作为内容来源比较完整的单元。

**已保留：** 原文、翻译、题目、选项、答案、解释、来源字段。

**仍缺：** 原书层面的词汇/构词/句法激活和口语 беседа 没有作为同一单元的结构化任务出现。

**建议落点：** Reader 增加“读后激活/口语”子任务；Skill 负责解释“为什么先读、再激活、再输出”；Agent 负责按作答结果生成迁移题。

**可信度：** 现有理解题 `可直接使用`；缺失的原书任务需回到章节页核对后再补。

### 样板 2：3.4.2《Лавр》

**为什么选它：** 它位于文学阅读部分，Reader 有 10 道题，同时具备 `translationSource` 和 `exerciseSource`，可检验“文学文本 + 深度阅读”是否只是题库化。

**已保留：** 文学原文、翻译辅助、理解题、答案字段。

**仍缺：** Skill 的“изучающее чтение”方法、文学文本的深层理解步骤、语言激活和口语输出没有在 Reader 单元中形成可见的阶段结构。

**材料风险：** 文学部分应保留 OCR/翻译的 `needs_review`；不能把 AI 翻译当成原书译文。

**建议落点：** Reader 增加“深读检查点”和口语复述/评价；Agent 负责解释文学语体、句法同义转换和观点表达。

### 差异样板 1：1.1.1《Достопримечательности Мурома》

**为什么选它：** 它是 Reader 的第一个单元，题目有答案和详细解释，但 JSON 顶层没有来源字段。

**问题：** 内容层看起来完整，证据层不完整。用户无法仅从数据判断答案来自印刷答案、OCR 交叉核对，还是后续 AI 整理。

**建议落点：** 暂不改题；先补来源审计记录。对于 Agent，回答时必须说“Reader 当前解释”或“AI 辅助讲解”，不能说成“原书解析”。

**可信度：** 题目可练；来源 `需核对`。

### 差异样板 2：2.1.2《Отчёт об экскурсии в музей》

**为什么选它：** 它使用 `judgement` 判断题，而不是大多数单元的 `choice`；同时只有 `exerciseSource`，数据结构与前后单元不完全一致。

**问题：** 判断题本身可能对应原书的查找/浏览阅读，但当前需要核对：题型是否忠实保留、答案如何核验、是否有中文提示、是否应该进入统一错题系统。

**建议落点：** 先做题型和答案来源核验，再决定是否统一为可解释的判断题记录；不要仅按选择题模板复制。

**可信度：** 题型可见；答案和教学解释 `需核对`。

## 7. 对白夜俄语 Agent 的职责与边界

本节只定义教学职责，不定义服务器、模型或代码实现。

### 7.1 Agent 应该做的事

| Agent 职责 | 应调用的资料 | 产出必须标记 |
|---|---|---|
| 解释阅读策略 | `v-mire-lyudei-reading-speaking`、`trki-b2-syllabus` | Skill/标准依据 |
| 解释某道题为什么选这个答案 | Reader 题面 + 原文锚点 + Skill 方法 | 原书答案 / AI 辅助讲解分开 |
| 生成读后迁移题 | 原文主题、Skill 的任务模式、用户错误证据 | AI 生成，不冒充原书 |
| 追问口语观点 | Skill 的 беседа / интенции + 原文主题 | AI 练习任务 |
| 分析重复错误 | Reader 的作答事件 + 语法/阅读 Skill | 事实、推断、待确认分开 |
| 安排下一步学习 | Reader 学习证据 + `trki-b2-syllabus` + 相关 Skill | 建议，不静默覆盖有效计划 |
| 解释跨书差异 | 17 个 Skill 的来源和范围 | 明确书名、来源、级别 |

### 7.2 Agent 不应该做的事

- 把 Book2Skill 的概括当作原书逐题答案；
- 把 AI 生成解释写成“作者解析”；
- 把不同作者的语法题库合并成无来源题库；
- 在 OCR 矩阵受损时编造答案；
- 因为某本 Skill 已生成，就宣称 Reader 已完整覆盖该书；
- 在没有学习证据时给出精确考试分数或通过概率。

## 8. 建议优先级

排序依据：学习价值、资料可靠性、对现有 Reader 的可落地程度。

### P0：先补证据链，不改题面

1. 为 `reading_speaking` 每个单元建立统一的来源状态：原书答案、OCR、人工核对、AI 辅助；
2. 优先核对 `ch0000`、`judgement` 单元和所有缺少来源字段的单元；
3. 保留原始章节只读，不直接覆盖 Reader JSON。

### P1：恢复阅读后的完整学习链条

1. 以 1.4.2、3.4.2 为样板，增加结构化的语言激活任务；
2. 增加每篇文本对应的口语 беседа/提纲/录音任务；
3. 把这些任务产生的完成、答案、录音或提纲作为 Reader 学习证据；
4. Agent 读取 Skill 的方法，Reader 执行任务，二者不重复保存同一事实。

### P2：建立跨书资料目录

建立一个机器可读的材料关系表，至少包含：

```text
skillId
readerModuleId
sourceBook
sourcePath
topic / taskType
evidenceType
confidence
```

这会让 Agent 能回答“这个题来自哪本书、该用哪套方法、下一步练什么”。

### P3：扩展其他 5 个 Reader 项目审计

按同一模板继续审计听力、听力模拟、写作口语、语法词汇和俄语 B2 全模块；优先检查：

- 听力音频、转写、答案与口语任务是否一一对应；
- 写作体裁和参考答案的来源层级；
- 语法题的原书身份、答案、解析和错题证据；
- 综合 B2 模块中不同来源教材是否被清楚区分。

## 9. 本轮不做的事

- 不修改 Reader 页面或 JSON；
- 不修改 17 个 Skill；
- 不把所有原书题目批量导入 Reader；
- 不启动正式后端、DeepTutor 或外部模型；
- 不把模拟考试和语法词汇派生模块改名为独立教材；
- 不根据 OCR 缺失矩阵推测答案。

## 10. 结论

第一轮审计最值得推进的不是“再生成更多 Skill”，而是把现有材料的职责分开并连起来：

1. 用 MinerU/章节资料确认原书到底设计了什么；
2. 用 Skill 说明这些任务为什么这样安排；
3. 用 Reader 承载可完成、可记录的练习；
4. 用白夜俄语 Agent 做讲解、追问、迁移和计划建议。

这套分工能容纳 17 本资料，也不会迫使 Reader 变成一个巨大扫描书架。
