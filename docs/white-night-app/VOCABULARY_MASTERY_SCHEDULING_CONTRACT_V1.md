# Vocabulary 掌握估计与复习调度契约 v1

> 状态：第一阶段已确认契约  
> 算法：FSRS-6  
> 首次实现基线：`ts-fsrs@5.4.1` 稳定版  
> 数据来源：[`VOCABULARY_EVENT_CONTRACT_V1.md`](./VOCABULARY_EVENT_CONTRACT_V1.md)  
> 当前授权：确定算法与验收规则；不代表已经授权修改 Vocabulary 生产代码、安装依赖或迁移学习数据

## 1. 大白话结论

系统以后不再因为你刚点了一次“认识”，就直接宣布这个词“掌握度 5”。它会分别回答：

1. **这段记忆能稳定保持多久**；
2. **今天大约还有多大概率能独立想起来**；
3. **为了维持约 90% 的记忆率，哪一天应该再测一次**。

第一阶段采用成熟的 FSRS-6 算法，不自己发明一套积分。FSRS 是一个开放的间隔复习算法，它根据每次真实回忆的时间和结果，估算词的难度、记忆稳定期和当前可回忆率。

## 2. 为什么不是继续使用当前算法

当前 `scheduleLongTerm()` 是简化的 SM-2 风格规则：最近一次点“不认识 / 模糊 / 认识”会把 `mastery` 直接改成 `1 / 3 / 5`，再用 `interval × easeFactor` 计算日期。

这有三个根本问题：

- 刚看过答案后点“认识”，会立刻显示满掌握，但只能说明短期记住；
- `mastery` 同时被当成学习状态和记忆强度，无法说明今天是否已经到期；
- 一次失误或一次乐观自评对结果影响过大，缺少完整时间历史。

现有当日回炉队列仍然有价值，它解决“这次学习过程中几张卡后再来一次”。本契约只替换长期掌握估计和跨日调度，不把两层队列重新混在一起。

## 3. 三个算法结果

每个复习单元保存和展示三个不同结果：

| 结果 | 大白话含义 | 用途 |
| --- | --- | --- |
| `difficulty` | 这个记忆对象对当前学习者有多难，范围 1–10 | 影响以后稳定期增长速度，不直接展示成掌握分 |
| `stabilityDays` | 从刚复习完到预计可回忆率降至约 90% 的天数 | 作为掌握估计的主要依据 |
| `retrievability` | 按当前日期估算此刻能独立想起的概率，范围 0–1 | 判断是否到期及显示“预计可回忆率” |

`nextReviewDate` 是调度结果，不是第四种掌握度。长期复习日期安排在预计可回忆率接近目标值时；因为日期按整天取值，实际到期时可能略低或略高于 90%。

## 4. 算法和参数

第一阶段固定参数：

```json
{
  "algorithm": "FSRS-6",
  "library": "ts-fsrs",
  "libraryVersion": "5.4.1",
  "desiredRetention": 0.9,
  "maximumIntervalDays": 3650,
  "enableFuzz": false,
  "enableShortTerm": false,
  "weights": "使用并完整保存 ts-fsrs@5.4.1 的 FSRS-6 默认 21 参数"
}
```

参数解释：

- **目标记忆率 90%**：官方建议的通用起点，在记得更牢和每日工作量之间取平衡；
- **最长间隔 3650 天**：避免极稳定词被无限推远，同时不强迫每年重复已经非常牢固的词；
- **关闭随机扰动**：同一事件和参数在浏览器、本地数据库和未来服务器上必须算出同一日期；
- **关闭 FSRS 短时步骤**：同日回炉由现有会话队列负责，避免两套短时调度互相竞争；
- **完整保存默认权重**：不能只保存“默认值”三个字，库升级后默认值可能变化。

第一阶段不训练个人参数，也不训练 LoRA。未来只有积累至少 1000 次合格长期复习、覆盖至少 90 天，并且新参数在留出数据上的预测误差确实下降时，才允许提出个性化参数升级；升级必须产生新的 `parameterSetId`，不能改写旧参数。

## 5. 什么是一个复习单元

FSRS 不能直接给整个俄语单词只维护一个状态，因为“看见认识”和“能主动说出”不是同一种记忆。

复习单元由以下内容共同确定：

```json
{
  "reviewUnitId": "稳定随机标识",
  "lexemeKey": "ru:идти|verb",
  "senseId": "当前被学习的释义单元",
  "skill": "meaning_recognition"
}
```

第一版学习方向：

| `skill` | 测什么 |
| --- | --- |
| `meaning_recognition` | 看俄语词或语境，回忆当前释义 |
| `form_recall` | 看释义或语境，主动回忆俄语形式 |
| `listening_recognition` | 听到发音，识别词或词义 |
| `usage_production` | 在写作或口语中正确使用 |

加入正式生词本时，默认只激活当前释义的 `meaning_recognition`。其他方向只有在学习者实际练习或明确选择为目标后才激活；不能因为词典列出了十个罕见义项，就生成十套未学习进度。

## 6. 哪些结果可以进入 FSRS

### 6.1 合格条件

一次结果只有同时满足以下条件，才能成为长期有效回忆：

1. 明确指向一个正式复习单元；
2. 作答或自我判断发生在答案揭示之前；
3. 没有依赖会泄露答案的提示；
4. 题目和参考答案未被标记为争议、错误或待验证；
5. 结果来自客观判定，或来自学习者明确的回忆自评；
6. 是该复习单元当天第一次合格的独立回忆。

同一天后续回炉仍保存 `review_attempt_completed`，用于会话统计和困难分析，但不再作为第二次长期评分推高稳定期。

### 6.2 三个现有按钮如何映射

| 当前按钮 | FSRS 评分 | 必须满足的真实含义 |
| --- | --- | --- |
| 不认识 | `Again` | 答错、没想起、必须看答案或提示后才知道 |
| 模糊 | `Hard` | 在揭示答案前已经想对，但明显犹豫、不完整或需要重复一次不泄题的音频 |
| 认识 | `Good` | 在揭示答案前独立、完整地想对 |

第一阶段不显示 `Easy`。快速答对仍记为 `Good`，避免学习者因为感觉良好把间隔推得过远。

关键纪律：**忘了就是“不认识”，不能用“模糊”代替。** FSRS 把 `Hard` 当作成功回忆；如果忘记却点“模糊”，所有后续间隔都会偏长。

### 6.3 客观题映射

- 独立答错或未作答：`Again`；
- 独立答对但答案不完整、明显犹豫：`Hard`；
- 独立完整答对：`Good`；
- 看过答案、使用泄题提示后答对：本次长期评分仍是 `Again`；
- 只重复播放一次完整音频但没有文字提示，随后答对：听力单元可以记为 `Hard`；
- AI 生成题尚未经过质量确认：只保存待验证证据，不进入 FSRS。

反应时间可以帮助发现异常和解释“模糊”，但 FSRS-6 本身不使用反应时间，不能仅凭答得快自动记为 `Easy`。

### 6.4 不进入 FSRS 的行为

以下行为保留为学习证据，但不直接改变稳定期：

- 普通查词和词典缺词；
- 阅读接触；
- 刚看完释义后的确认；
- 同日第二次及后续回炉；
- AI 待验证的写作、口语或语境评价；
- 与目标词没有直接因果关系的阅读题错误；
- 有争议或已更正为无效的题目。

再次查询已毕业词条只设置“需要诊断”标记，并把对应单元放入最近一次可用复习；只有诊断中的真实 `Again / Hard / Good` 才更新 FSRS。

## 7. 同日回炉怎么算

同日回炉帮助学习，但不冒充长期记忆。第一阶段统一规则：

| 当次结果 | 本轮安排 |
| --- | --- |
| `Again` | 约 3 张其他卡后再次出现 |
| `Hard` | 约 6 张其他卡后再次出现 |
| `Good` | 本轮通过 |

- 某单元当天第一次合格结果立即进入 FSRS；
- 如果第一次是 `Again`，后来回炉答对，长期结果仍保留 `Again`，下次通常安排到次日；
- 连续三次仍是 `Again` 时结束强制回炉，标为困难并安排次日，不制造无法结束的会话；
- 卡组太小时允许提前回炉，但界面必须标明这是短时确认；
- 撤销评分通过更正事件重算，不直接篡改历史。

## 8. 掌握度怎样显示

### 8.1 不再使用 0–5 作为算法真值

页面可以继续用进度条或标签，但底层不再保存“掌握度 5”作为事实。每个复习单元根据 `stabilityDays` 和有效回忆历史得到以下等级：

| 等级 | 条件 |
| --- | --- |
| 未测 | 还没有合格长期回忆 |
| 初学 | 已有结果，但 `stabilityDays < 3`，或最近一次遗忘后尚未形成两个不同日期的成功回忆 |
| 形成中 | `3 ≤ stabilityDays < 21`，并且最近一次遗忘后至少有两个不同日期的成功回忆 |
| 稳定 | `21 ≤ stabilityDays < 90`，并且最近一次遗忘后至少有三个不同日期的成功回忆，时间跨度至少 7 天 |
| 牢固 | `stabilityDays ≥ 90`，并且最近一次遗忘后至少有四个不同日期的成功回忆，时间跨度至少 30 天 |

如果稳定期达到阈值但证据跨度不足，停留在前一级。一次 `Again` 会让 FSRS 重新估算较低稳定期，并重新开始“最近一次遗忘后”的成功证据统计，但不会删除之前的历史。

### 8.2 到期不是掌握等级

页面另外显示：

- `预计可回忆 94%`：当前 `retrievability`；
- `今天复习`：`nextReviewDate` 已到；
- `可能遗忘，待诊断`：已毕业后再次查词，但尚未完成诊断。

一个“牢固”的词长时间没复习后可以处于“已到期”，但在真正测试失败前，不因为日历过去就直接改成“初学”。

### 8.3 词条总体掌握

总体状态只聚合已经激活的释义和学习方向：

1. 一个释义的状态取其**必修学习方向中的最低等级**；
2. 一个词元的总体状态取其**已激活释义中的最低等级**；
3. 选修方向单独显示，不拖低总体状态；
4. 未遇到的罕见释义不参与；
5. 存在待确认词形或争议证据时显示提示，但不偷偷归入某个词元。

第一阶段默认只有 `meaning_recognition` 是必修，因此不会因为尚未练口语或听力让所有单词都显示未掌握。

## 9. 下一次复习时间怎样算

每次合格长期回忆完成后：

1. 读取该复习单元上一次 FSRS 状态；
2. 计算距上次合格长期回忆的实际天数；
3. 将 `Again / Hard / Good` 和实际间隔交给固定版本 FSRS；
4. 得到新的 `difficulty`、`stabilityDays` 和建议间隔；
5. 从实际复习日加上整数间隔，得到 `nextReviewDate`；
6. 保存本次使用的 `algorithmVersion`、`libraryVersion`、`parameterSetId` 和派生结果；
7. 到期日按学习者本地时区判断，当前默认 `Asia/Shanghai`。

逾期复习按真实逾期天数计算，不假装按时完成。提前复习也按真实间隔计算，不能通过反复提前刷词无限推远下次日期。

到期选择规则：

- 所有已到期复习都进入今日队列，不受“今日新词上限”挤掉；
- 新词上限只控制今天首次引入多少新复习单元；
- 同一词条多个复习单元同时到期时可以在界面错开，但每个单元的原始到期日必须保留；
- 数据库或 Node 不可用时，本地照常计算和保存，恢复后按事件补交。

## 10. 毕业与重新进入

正式生词本词条满足以下条件时毕业：

- 所有已激活释义的必修复习单元至少达到“稳定”；
- 没有未解决的词元归属问题；
- 没有会推翻结果的争议证据；
- 当前不存在当天未完成的到期复习。

毕业只表示退出高频学习和每日新词队列，未来仍按 FSRS 到期复习，不删除词条、事件或复习单元。

以下情况触发重新诊断或重新进入高频复习：

- 合格复习得到 `Again`；
- 同一已毕业释义短期内再次查词；
- 经人工确认的写作或口语错误直接涉及该复习单元；
- 词元或释义归属被更正。

普通到期复习不叫“重新进入”，它只是正常的长期维护。

## 11. 旧进度怎样迁移

现有 `mastery`、`interval`、`easeFactor` 和有限 `history` 不能可靠换算成 FSRS 的稳定期，因此采用渐进校准：

1. 原记录完整保存在 `legacy_vocabulary_snapshot_imported`；
2. 不把旧 `mastery=5` 伪造成一次 `Good`；
3. 不根据旧 `interval` 反推虚构稳定期；
4. 旧 `nextReview` 在 30 天内时暂时保留为校准日期；
5. 旧日期已过、缺失或超过 30 天时，按稳定散列分布到未来 1–30 天，避免迁移当天出现复习洪峰；
6. 第一次真实合格回忆后，用实际评分初始化 FSRS 状态；
7. 双写核对完成前，旧记录继续保留且可回滚。

迁移后的词在第一次真实测试前显示“待校准”，不能显示为 FSRS 已确认的“稳定”或“牢固”。

## 12. 固定样例验证

以下结果已用 `ts-fsrs@5.4.1`、FSRS-6 默认 21 参数、目标记忆率 0.90、最长间隔 3650 天、关闭随机扰动和短时步骤实际计算。日期从 2026-01-01 开始：

| 场景 | 下次日期 | 新稳定期 | 说明 |
| --- | --- | --- | --- |
| 新单元第一次 `Again` | 2026-01-02 | 0.2120 天 | 次日再测 |
| 新单元第一次 `Hard` | 2026-01-03 | 1.2931 天 | 成功但很吃力 |
| 新单元第一次 `Good` | 2026-01-04 | 2.3065 天 | 三天后再测 |
| 第一次 `Good`，到期再次 `Good` | 2026-01-18 | 13.8269 天 | 稳定期明显增长 |
| 第一次 `Good`，到期得到 `Again` | 2026-01-05 | 0.6369 天 | 稳定期下降，次日再测 |

新单元第一次 `Good` 后，实测当天可回忆率为 100%，第二天约 94.68%，整数到期日约 88.09%。这说明“目标 90%”是调度目标，不是保证每张卡在整天边界上精确等于 90%。

生产实现必须把这些样例做成自动化测试。任何库升级、参数变更或时区修改，只要结果变化，就必须通过新的算法版本和迁移说明明确处理。

## 13. 验收标准

算法实现只有同时满足以下条件才算完成：

1. 同一事件序列和参数在刷新、重启和另一设备重放后得到相同状态；
2. 三个现有按钮严格映射为 `Again / Hard / Good`，不显示 `Easy`；
3. 看答案后的“认识”不能记成独立 `Good`；
4. 同日回炉不会多次推高长期稳定期；
5. 到期、逾期和提前复习都使用实际发生时间；
6. 掌握等级、当前可回忆率和下次复习日期分别展示和保存；
7. 查词、阅读接触和 AI 待验证证据不能直接改变 FSRS；
8. 旧 `mastery=5` 不会自动变成新“牢固”；
9. 旧进度渐进校准，不在迁移当天制造复习洪峰；
10. 数据库和网络不可用时仍可本地复习、刷新恢复并补交事件；
11. 撤销和证据更正能通过重放得到正确状态；
12. 固定样例、边界日期和时区测试全部通过。

## 14. 仍未决定

本契约没有提前决定：

- 页面具体怎样画稳定期、预计可回忆率和到期提示；
- 学习者是否可以在设置中调整目标记忆率；第一阶段固定为 90%；
- 考试前临时冲刺是否使用独立的更高目标记忆率；
- 复习单元在界面中的创建、合并和停用交互；
- 个人参数优化工具何时进入产品；第一阶段不实现；
- FSRS 状态在本地数据库中的物理表结构和索引。

这些问题可以后续决定，但不能重新把最近一次自评当成掌握真值，也不能让 AI 直接决定长期间隔。
