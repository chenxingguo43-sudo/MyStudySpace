## 0. 这份文档解决什么

本文件把“借鉴同译同学的理念优化 Reader”和“建设白夜俄语 Agent”连接成一条产品链，同时避免把同译同学本身接入白夜俄语。

一句话结论：

> Reader 和 Vocabulary 产生可靠学习证据，统一学习数据层负责保存和计算，白夜俄语 Agent 按需读取证据并提供可追溯的分析与计划。

```text
同译同学的产品灵感
        ↓
Reader 查词与情境猜词
        ↓
Vocabulary 复习与掌握估计
        ↓
统一学习数据层
        ↓
白夜俄语 Agent 分析、解释与规划
```

同译同学只是灵感来源。第一阶段不读取它的 `wordlist.json`，不为它预留专用接口，也不让两个程序互相依赖。

## 1. 第一阶段范围

第一阶段只完成一个可验证闭环：

```text
Reader 成功查词
  → 可选情境猜词
  → 学习者决定是否加入正式生词本
  → Vocabulary 安排复习
  → 算法更新掌握估计和下次复习时间
  → 学习证据可供未来白夜俄语 Agent 查询
```

第一阶段不同时建设：

- 语法题完整 AI 解析；
- 阅读题完整 AI 解析；
- 写作和口语完整 AI 导师；
- 个人 LoRA 训练；
- 多用户账号、登录和权限；
- 同译同学数据导入或程序改造；
- 生产级服务器同步；
- Penguin-Harness 或 DeepTutor 与正式学习数据的连接。

## 2. 角色和数据权威

### 2.1 Reader

Reader 是阅读、查词和情境猜词的入口。它负责即时保存客观行为，不负责宣布学习者永久掌握了某个词。

### 2.2 Vocabulary

Vocabulary 管理学习者明确确认的正式生词本、复习活动、掌握估计和复习计划。查词历史不自动等于正式生词本。

### 2.3 学习数据层

学习数据层保存学习事件、当前可重建状态、来源、设备和必要的内容快照。原始证据、算法结果、AI 推断和人工修正必须可区分。

### 2.4 白夜俄语 Agent

Agent 可以读取相关证据、保存明确标注的推断并提出计划，但不能覆盖原始学习事件，也不能用一次模型输出直接决定掌握或毕业。

### 2.5 算法与 AI 的分工

可解释算法负责掌握估计、复习时间和毕业判断。AI 负责语境判断、定性评价、解释和建议；AI 结果默认属于待验证证据，除非被后续客观证据印证。

## 3. Reader 查词流程

### 3.1 什么算有效查词

只有词典成功显示结果，才记录一次有效查词。

- 短时间内对同一词、同一上下文的连续点击合并为一次；
- 误触和加载失败不计入有效查词；
- 查不到的词单独记录为“词典缺词”，用于完善词库；
- 词典缺词不能直接影响掌握估计。

Phase 2 当前实现使用 15 秒去重窗口。它是可根据真实使用调整的实现参数，不是永久算法常量。

### 3.2 有效查词保存什么

每次有效查词保存：

- 实际点击的词形；
- 当时识别出的原形及其确认状态；
- 所在句子；
- 教材、章节和句子位置；
- 当时展示或采用的释义；
- 查词时间和设备来源；
- 是否进入情境猜词；
- 是否加入正式生词本。

保存稳定内容编号，同时保存判断所需的最小内容快照。不得为了保留一次查词而复制整本教材。

### 3.3 普通查词模式

点击单词后立即显示现有词典结果。普通查词不弹出“是否加入生词本”的阻断式对话框，只提供明确的加入按钮。

### 3.4 先猜模式

学习者可以主动开启“先猜模式”。开启后：

1. 暂不显示目标释义；
2. AI 生成两句新的俄语语境；
3. 提供三个中文释义选项；
4. 学习者作答；
5. 再显示词典释义、AI 语境判断和解释；
6. 在结果区询问是否加入正式生词本。

先看释义再练习的结果只能作为弱证据；先猜模式的结果可以作为较强证据，但因题目由 AI 生成，仍需保留题目质量和争议处理能力。

## 4. 词条、释义与原形

### 4.1 一个词元一个主词条

Vocabulary 中一个正式词元只保留一个主词条。正式身份由“保留 `ё` 的规范原形 + 标准化词性”共同确定；只含原形不足以区分同形不同词性的词。再次遇到同一词元时，新增释义、例句、词形和证据，不创建重复主词条，也不覆盖旧内容。具体规范和迁移规则以第一版词汇事件契约为准。

### 4.2 总体状态与细分状态并存

每个词条同时拥有：

- 面向快速浏览的总体掌握估计；
- 各释义单元的掌握情况；
- 重要词形和用法的掌握情况；
- 每项结论所依据的证据。

总体掌握估计只计算学习者实际遇到、主动学习或当前目标要求的释义。罕见且从未遇到的释义不能永久拖低总体状态。

### 4.3 原形歧义

同一词形可能来自多个原形或词性。AI 或形态分析可以先给出最可能结果，但不确定时必须标记为“待确认”。

- 证据足够时由算法自动确认；
- 仍然模糊时，在 Vocabulary 复习流程中偶尔请求学习者二选一；
- 不在 Reader 阅读过程中强制弹窗；
- 正式确认前，不得污染某个词条的可靠掌握证据。

## 5. 查词历史与正式生词本

查词历史自动保存所有有效查词；正式生词本只保存学习者明确确认需要复习的词条。

```text
查过一个词 ≠ 已加入 Vocabulary
```

如果一个未加入生词本的词在一段时间内反复被查询，Agent 或规则可以建议加入，但必须由学习者确认，不能自动塞入正式生词本。

## 6. 掌握估计与复习计划

### 6.1 两个不同结果

系统必须分别计算：

- **掌握估计**：当前证据表明这个词、释义或用法有多稳定；
- **复习计划**：下一次应在什么时候、以什么方式复习。

刚刚答对不等于长期稳定；长时间没有复习也不代表掌握立即归零。

第一阶段长期掌握与跨日调度采用 FSRS-6：记忆稳定期作为掌握估计的主要依据，当前可回忆率决定是否接近到期，目标记忆率固定为 90%。同日回炉仍由独立会话队列管理。具体评分映射、毕业阈值、旧进度校准和固定验收样例以算法契约为准。

### 6.2 证据强度

证据按可靠程度分层，具体权重留给后续算法设计：

| 证据 | 默认强度 | 说明 |
| --- | --- | --- |
| 延迟后主动回忆、拼写或正确产出 | 强 | 更接近真实长期记忆 |
| Reader 中明确考查该词且答对 | 中到强 | 必须能确认题目考查对象 |
| Vocabulary 语境选义 | 中 | 需考虑猜中和题目难度 |
| 先猜模式正确 | 中 | AI 生成题目先保留质量风险 |
| 看完释义后的练习 | 弱 | 只能证明短时识别 |
| 自评“认识” | 很弱 | 只作辅助，不主导评分 |
| 阅读接触 | 很弱 | 只表示可能见过，不直接提升掌握 |
| AI 对写作或口语的正确使用判断 | 待验证 | 被其他证据印证后才能增强可信度 |
| 再次查词、明确答错或错误使用 | 反向 | 影响大小取决于重复性和证据质量 |

### 6.3 单次错误

一次答错只产生有限影响。系统应结合近期重复错误、题目质量、测试方式、时间间隔和后续表现，再决定是否明显降低掌握估计。

做错一道阅读题不能降低文章中所有单词的掌握估计。只有题目明确考查某词，或证据确认错误与该词有关，才能产生直接影响。Agent 的错因猜测只能先保存为推断。

### 6.4 再次查词

再次查询已掌握词条时，先标记“可能遗忘”，不得立即大幅降级。系统随后结合：

- 查询间隔；
- 查询的是基础义、特殊义、重音还是词形；
- 后续小测试；
- Reader 中的理解结果；
- 是否短期重复查询；

再决定影响哪个释义单元或词形状态。

### 6.5 阅读接触

只有句子真实进入可见区域、页面保持活动并达到合理停留条件，才记录一次低可信阅读接触。打开整章不能视为读过整章。

阅读接触与掌握证据分开保存，不得靠累计页面曝光把词条提升为掌握。具体可见比例、停留时间和单次会话去重规则留待实现验证。

### 6.6 毕业和重新进入复习

词条达到稳定条件后暂时退出日常复习队列，但不删除历史。毕业条件由可解释算法根据间隔、测试难度、正确与错误历史等分别计算，不使用“全部连续答对固定次数”的单一规则，也不交给 AI 直接决定。

词条在再次查词、明确答错或错误使用后，可以重新进入复习队列。

## 7. 共同学习事件骨架

第一阶段先为所有学习模块定义共同骨架，再优先细化词汇事件。每条事件至少需要回答：

```text
谁在学习
来自哪台设备
什么时候发生
来自哪个模块
学习对象是什么
采取了什么行为
结果是什么
证据来自哪里
判断所需的最小内容快照是什么
```

概念字段包括：

- 全局唯一事件编号；
- 学习者标识；
- 设备标识；
- 事件类型；
- 发生时间和接收时间；
- Reader、Vocabulary 等来源模块；
- 教材、章节、题目、词条或释义单元标识；
- 客观结果；
- 必要内容快照；
- 证据类型和可信级别；
- 关联事件或更正对象。

共同骨架、词元身份和逐类必填字段已经细化在 [`VOCABULARY_EVENT_CONTRACT_V1.md`](./VOCABULARY_EVENT_CONTRACT_V1.md)。它是领域契约，不是已经确认的数据库表结构。

### 7.1 第一阶段词汇事件清单

| 事件 | 含义 |
| --- | --- |
| 有效查词 | 词典成功显示并通过短时去重 |
| 词典缺词 | 查询成功发起但词典没有可用结果 |
| 阅读接触 | 满足低可信可见与停留条件 |
| 情境猜词完成 | 保存题目快照、选择、结果和题目来源 |
| 正式加入生词本 | 学习者明确确认加入 |
| 复习作答完成 | 保存测试方式、答案、结果和时间间隔 |
| 实际使用评价 | 写作或口语中与该词有关的客观或待验证证据 |
| 原形确认 | 将待确认词形归入正式词条 |
| 毕业 | 词条暂时退出日常复习 |
| 重新进入复习 | 新证据触发词条回到复习队列 |
| 证据更正 | 对错误答案、错误归因或错误内容作追加修正 |
| 隐私删除 | 按学习者要求永久清除指定私人内容 |

## 8. 事实、算法结果与 AI 推断

系统必须区分：

1. 客观学习证据；
2. 用户明确确认；
3. 可解释算法的派生结果；
4. AI 待验证证据；
5. Agent 推断；
6. 人工修正或复核。

AI 语境义、写作评价和错因分析不能伪装成正式词典事实。个人 AI 释义可以保存、编辑和删除，但不能覆盖正式词典内容。

普通错误通过追加更正记录处理，不偷偷改写历史。涉及隐私的内容必须允许真正永久删除，并处理仍含该内容的旧备份。

## 9. Agent 如何使用学习数据

本方案不训练个人 LoRA。白夜 Agent 使用的是“按需查询学习数据”的方式：

1. 先读取学习概况；
2. 根据当前问题查询相关原始证据；
3. 区分事实与推断；
4. 给出依据；
5. 将需要长期保留的判断保存为可推翻的 Agent 推断。

Agent 可以根据重复查词、到期复习和当前阶段目标，把适量任务加入今日计划，但必须说明原因，并允许学习者跳过、调整或删除。

在线 AI 只能接收当前任务所需的最少数据。昵称、设备信息和无关历史不得发送；写作原文、口语转写等敏感材料应按具体功能明确提示。

## 10. 从浏览器记录迁移到本地数据库

迁移采用“先复制、核对、再交接”：

```text
阶段一：浏览器继续作为当前记录来源
        + 本地数据库自动接收备份副本

阶段二：连续核对数据完整性、重复同步和恢复结果

阶段三：本地数据库成为正式总账
        + 浏览器保留离线副本和待同步队列
```

数据库或本机 Node 服务不可用时，Reader 和 Vocabulary 的基础学习、即时保存和复习不能停止。恢复后按全局唯一事件编号补交，重复上传不能重复计分。

当前只服务一个学习者，不建设账号系统。数据仍预留学习者和设备标识，由系统自动管理，不要求当前用户注册或命名设备。

未来多设备同时离线学习时，分别保留每次学习事件，再合并证据并重新计算派生结果。不得采用“最后上传的整份进度覆盖其他设备”的策略；真正冲突的人工修改才需要学习者选择。

本文件本身不决定物理实现；第一阶段本机 SQLite、浏览器 outbox、接口和迁移门槛已经在下位迁移方案中确定。该选择只适用于本机实验，不决定未来正式服务器架构。

## 11. 备份、导出与控制权

- 本地数据库负责日常自动保存；
- 本机保留最近若干份滚动备份；
- 允许选择另一个文件夹或移动硬盘保存第二份；
- 第一阶段不要求云端备份；
- 继续提供可携带、可校验的 JSON 学习档案；
- 数据库备份用于故障恢复，JSON 用于查看、迁移和避免产品锁定；
- 具体备份数量、周期、加密和恢复流程留待数据库设计阶段确认。

## 12. 与 Penguin-Harness 和 DeepTutor 的边界

本蓝图不改变已确认的 Agent 实验顺序。

- Penguin-Harness 和 DeepTutor 第一轮仍只使用固定模拟数据；
- 两个实验都不能读取或写入正式 Reader/白夜数据库；
- 实验 Trace 不能冒充学习事件；
- 候选能力只有在完成“采用 / 适配 / 重写 / 放弃”判断后，才能进入白夜产品边界；
- 最终只有一个面向用户的白夜俄语 Agent。

## 13. 关键边界场景

### 场景一：短时间重复点击

同一词、同一上下文因页面卡顿连续点击，只形成一次有效查词；失败点击不增加查词次数。

### 场景二：同词不同义

`идти` 在“步行”和“事情进展”两个语境中出现时，归入同一主词条下的不同释义单元，分别积累证据。

### 场景三：词形歧义

`стали` 无法确定来自 `стать` 还是 `сталь` 时先保留待确认记录，不污染任何正式词条；证据不足时延后到 Vocabulary 询问。

### 场景四：阅读题做错

阅读题做错只保存题目结果。没有直接证据时，不降低文章中所有词的掌握估计；Agent 可以提出待确认错因。

### 场景五：再次查已毕业词

再次查询只触发“可能遗忘”。后续测试或重复错误确认后，才降低对应释义并让词条重新进入复习。

### 场景六：AI 题目有误

学习者标记题目或答案有争议后，本次结果不得作为可靠掌握证据；原结果保留并追加更正，供后续审计。

### 场景七：服务不可用

本机数据库或在线 AI 不可用时，普通查词、现有词典、基础复习和浏览器保存继续工作；恢复后再同步。

## 14. 第一阶段验收标准

第一阶段只有同时满足以下条件才算完成：

1. 有效查词、短时去重和词典缺词可以被稳定区分；
2. 每次有效查词保存词形、原形状态、句子、来源位置和当时释义；
3. 普通查词不被 AI 或数据库可用性阻断；
4. 先猜模式按“两句俄语语境 + 三个中文选项 + 作答后揭示”工作；
5. 查词历史不会自动污染正式生词本；
6. 同一原形不会因不同语境产生重复主词条；
7. 原形歧义可以延后确认且不污染可靠证据；
8. 掌握估计和复习计划彼此分离；
9. AI 证据、Agent 推断和客观事实可被明确区分；
10. 毕业词条保留历史，并能因新证据重新进入复习；
11. 浏览器旧数据在数据库迁移验证完成前不被删除或降级；
12. 数据库、Node 或在线 AI 不可用时仍能完成基础学习；
13. 重复同步不会造成重复查词、重复计分或重复复习；
14. JSON 导出、数据库备份和隐私删除边界有可验证结果；
15. 相关自动化测试及受影响的桌面、移动浏览器流程完成实际验证。

## 15. 尚未决定

以下内容不得根据本蓝图自行假设：

- 浏览器旧数据的详细迁移映射；
- 查词短时去重窗口；
- 阅读接触的可见比例和停留时间；
- 非 FSRS 证据如何形成辅助诊断分，不得覆盖 FSRS 状态；
- 先猜模式的具体入口、默认设置和视觉方案；
- AI 供应商、模型、价格和密钥配置；
- 第二备份位置和应用层加密方式；
- 未来服务器、数据库、鉴权和部署方案；
- 语法、阅读、写作与口语 AI 解析的后续阶段范围。

## 16. 下一步

1. 对照现有 Reader、Vocabulary、学习档案和活动记录代码，完成只读差距盘点；
2. 以本机 SQLite 双写方案为准，形成逐任务生产实施计划和测试清单；
3. 获得用户明确授权后再修改生产代码。
