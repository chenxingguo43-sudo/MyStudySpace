## 目标

在 `D:\MyStudySpace\俄语资料库\` 新建一个独立的 Obsidian Markdown 学习项目。它必须保留 `E:\Desktop\俄语B2.pdf` 的 190 页原书证据，同时以“刷题优先”的阅读方式提供可搜索文本、语法逐题解析和按需展开的学习辅助。

旧目录 `D:\MyStudySpace\俄语资料库\俄语B2 全模块 Markdown版` 保持不变，仅可作为 OCR 对照材料，不作为新项目的唯一来源。

## 成功标准

- 原书 190 页均可从新项目本地打开、查看和核对；不依赖外部图片链接。
- 每个学习单元可追溯到明确的原书页或连续页范围。
- 学习层与原书内容分离：AI 解释、中文提示、范例和答案解析均带明确标签。
- 语法选择题按短题组组织，题目和选项默认可见；答案、解析与提示默认折叠。
- 学习单元在 Obsidian 阅读视图、Live Preview、暗色主题和窄屏窗口中均保持清晰可用。
- 原书的题目、选项、答案区、表格、范文和图片不因 OCR 重排而失去边界。
- 项目质量报告只陈述实际通过的验证结果；没有页码级映射时不得称为完成。

## 范围与非目标

本项目完整覆盖语法词汇、阅读、写作、听力、会话与真题六个模块，按模块逐批交付。第一批为“语法词汇：逐题解析”。

本项目不尝试以 Markdown 像素级重画扫描书。扫描页图是原书视觉的权威载体；Markdown 是可搜索、可学习的语义层。项目不使用网络 CDN 保存原书图片，也不把 AI 生成内容伪装为原书答案。

## 三层内容模型

### 1. 原书复刻层

`原书/俄语B2.pdf` 是只读来源副本。PDF 每页已经包含一张 JPEG 扫描图，`页图/` 优先直接提取该原始 JPEG，不重新渲染为 PNG；只有存在旋转、裁切或颜色异常的页面才生成修正预览。文件名与 PDF 页序一一对应。每个 `原书页/PDF-NNN.md` 显示本地页图、PDF 页码、书内印刷页码（若可识别）、上一页/下一页、该页的简短目录标签，以及同页 OCR 与学习单元的链接。

该层负责视觉忠实性。遇到表格、信件格式、答题卡、插图或版式复杂页时，以页图为准，不通过猜测性 Markdown 重绘替代。

### 2. 可搜索整理原文层

`原始OCR/page_NNN.json` 记录逐页 OCR 结果、文本块、坐标和 OCR 风险。JSON 避免原始 OCR 与整理原文同时污染 Obsidian 全局搜索；人类阅读入口始终是 `整理原文/`。`整理原文/` 按模块与题型拆成多个短文件，将 OCR 重建为可读教材 Markdown：题干、选项、对话、范文、答案区、表格和图注均分块书写，并在每个任务块保留紧凑的 `[[原书页/PDF-NNN]]` 链接。

只有在原书页与 OCR 互相核对后，内容才可进入 `整理原文/`。不确定字符、缺失转录、听力材料缺页和复杂图表使用 `needs_review` 明示。

### 3. 刷题优先学习层

学习单元从整理原文引用任务，不复制大段 OCR。语法学习单元按一个题型或 8–12 题的连续题组拆分。每个单元顶部有：题组范围、`查看原书页`、`查看整理原文`、上一单元/下一单元和作答说明。

默认阅读顺序：题目与选项 → 心中或纸笔作答 → 每题一个折叠的“答案与解析”区 → 错因与复习提示。第一版不模拟网页单选按钮，不承诺自动判题。折叠区内部必须分别标注原书答案、原书解析（若有）与 AI 参考解析。生成的参考解释使用 `参考解析（AI，待复核）`；不得置入 `原书内容` callout。

### 4. 学习记录层

学习记录不与原始题目混写。每个单元使用 frontmatter 保存 `status`、`mastery`、`wrong_questions` 和 `last_review`，`学习记录/语法进度.md` 通过已安装的 Dataview 汇总进度。选项不使用现有任务复选框，因为当前 CSS 会将勾选行显示为删除线；第一版以折叠自测和错题编号记录为准。

## Obsidian UI 合同

每个学习单元必须声明 `cssclasses: [russian-reading, b2-quiz]`。现有 `russian-reading` 负责正文宽度与俄语阅读排版；新增的 `b2-quiz` 只负责题号、选项间距、原书页导航和折叠答案的点击尺寸，不改变整个知识库的通用 callout。

桌面端内容列宽以 760–900px 为宜，俄语题干不小于 18px，选项不小于 16px，折叠标题不小于 14px，并提供足够的垂直点击区域。暗色与亮色主题均不得只靠颜色表达“原书答案”和“AI 解析”的区别。窄屏下保持单列，不出现横向滚动；表格和长链接需要可换行。

桌面端利用 Obsidian 已启用的 Page Preview 悬停查看原书页，也允许在新窗格打开。移动端没有悬停能力，因此原书页必须有清晰的返回路径和上一页/下一页导航。

## 索引与可追溯性

`_data/source_manifest.json` 记录 PDF 的文件名、页数、哈希、生成日期、每页原始图像尺寸和页图文件名。`_data/range_map.json` 与 `索引/原书页—题目—学习单元地图.md` 记录模块、题组、`question_pages`、`answer_pages`、`explanation_pages`、`media_pages`、整理原文文件及学习单元文件的完整对应关系。

映射以 PDF 页码为主；若书内印刷页码不同，则同时存储并清楚标注。任何无法从 PDF 确认的题目边界进入 `needs_review`，不以推断补齐。

## 交付顺序

1. 创建最小项目骨架和自动化状态文件。
2. 选择至少 5 个代表页：普通题目页、答案/解析页、复杂表格页、写作版式页和图片页；直接提取 JPEG 并核对方向、裁切和清晰度。
3. 制作一个包含 8–10 道语法题的真实 Obsidian 试制单元与 `b2-quiz` CSS。
4. 在阅读视图、Live Preview、暗色主题、窄屏窗口和移动端检查字体、折叠、导航、页图预览和学习记录；试制未通过不得批量生产。
5. 试制通过后导入 PDF 副本，提取并核对 190 张本地页图，创建 190 个原书页 Markdown，建立页级来源基础。
6. 逐页 OCR，先产出页面 JSON，再构建可读的整理原文与范围地图。
7. 生成并审核语法词汇的短题组学习单元与逐题解析。
8. 以同一规则推进阅读、写作、听力、会话和真题。
9. 运行来源、范围、可读性、学习单元与翻译层验证，编写最终质量报告和封版说明。

## 质量门槛

- 页数、页图数、原书页 Markdown 数均为 190，且一一对应；页图优先为 PDF 内嵌原始 JPEG。
- 页面链接为本地相对链接；项目内不保留原书内容的网络图片 URL。
- 每个范围地图条目至少有一个 PDF 页范围、一份整理原文和一个学习单元（尚未完成的批次必须显式标为 `pending`）。
- 整理原文没有粘连的长题干/选项，也没有以一整块原始 OCR 代替教材文本。
- 学习单元不复制长篇整理原文，答案和 AI 生成解析均可折叠且来源明确。
- 试制单元在阅读视图、Live Preview、暗色主题和窄屏窗口中没有文字小于规范、横向溢出、点击区域过小或来源导航失效。
- 项目仅能在所有验证项通过时称为 `PASS`；若 OCR、转录或音频材料存在未决风险，只能标为 `PASS with known risks`。

## 本地资产与同步策略

原始 PDF 约 68MB，直接提取的 190 张 JPEG 预计再占约 50–75MB。它们是本地学习资产，但默认不进入普通 Git 提交，以避免仓库膨胀；Markdown、JSON 清单、CSS、校验脚本和质量报告可以纳入版本控制。若用户希望跨设备保留扫描页，应通过当前 Obsidian Sync 同步，或另行启用 Git LFS 后再改变策略。

## 风险处理

该 PDF 为扫描件，文本提取本身不可作为原书事实依据。OCR 漏字、页面倾斜、插图、答题卡、视频/音频缺少转录以及书内答案与任务跨页，均以页图和连续页映射处理。任何自动生成的中文、语法解释或范例均默认 `needs_review`，直至人工复核。
