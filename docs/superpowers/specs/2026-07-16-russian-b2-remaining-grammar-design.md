# 俄语 B2 剩余语法题库：发布设计

## 目标

完成整套语法模块 P1–P6：第 2 部分“接格关系（1–70）”已发布；第 1、3、4、5 部分的全部独立语法选择题均须完成；第 6 部分纳入能够脱离阅读和公文任务而独立作答的语法题。最终读者在同一个网页阅读器中完成练习、查看经原书核对的答案与解析，并获得稳定的学习进度。

## 范围

### 纳入

- 第 1 部分：词形、动词体和时态等独立语法选择题。
- 第 3 部分：形动词、副动词等独立语法选择题。
- 第 4 部分：关系词、复句及相关独立语法选择题。
- 第 5 部分：原书中独立呈现、可单题作答的全部语法选择题。
- 第 6 部分：能够提取为独立题干、四个选项和单一答案的语法选择或填空题。

### 不纳入

- 第 6 部分中依赖整篇阅读材料才能作答的题目。
- 公文写作、信件写作、翻译或开放作答任务。
- OCR 无法还原题干、选项和答案，且原书扫描件也无法可靠判定的题目；这些题保留 `needs_review`，不发布为已核对题目。

## 学习体验

每 10 道印刷题为一个单元。用户先选择并确认答案；此时只展示对错。用户点击“查看答案与解析”后，固定按下列顺序展开：

1. 原书答案（已核对）；
2. 原书解析（已核对），含原书译文；
3. 参考解析（AI，待复核）；
4. 易错点；
5. 原书页码。

阅读器仍使用“教材 ID + 单元永久 ID”保存练习完成状态，不使用章节下标。确认或展开解析时保持当前滚动位置。

## 数据与原书追溯

每个语法部分建立独立的来源台账，最少记录：印刷题号、永久题目 ID、题页、规则页、答案页、原书答案、原书解析、原书译文和核对状态。台账必须声明完整题号范围；校验器将拒绝缺号、重复号、答案不一致、缺少解释/译文或缺少证据页的发布数据。

OCR Markdown 只充当定位线索。题干、选项、答案、规则和译文的最终依据均为 `E:\Desktop\俄语B2.pdf` 的对应扫描页。

## 构建结构

- 规范题目数据：`俄语资料库/俄语B2·原书复刻与学习版/规范数据/语法词汇/`
- 来源台账：同目录的按部分命名 `part-XX-source-ledger.json`
- 清单：同目录 `index.json`
- 阅读器产物：`data/textbook/russian_b2/chNNNN.json`
- Obsidian 学习单元：`俄语资料库/俄语B2·原书复刻与学习版/学习单元/语法词汇/`
- 派生范围图与质量报告：沿用现有 `_data/range_map.json` 和 `质量报告/grammar-units.json`

现有通用构建器负责生成所有派生输出。需要扩展时应修改清单/数据契约或构建器，而不是在 `reader.html` 中为某一部分添加硬编码分支。

## 分批顺序

1. 完成第 1 部分的题号范围确认、PDF 页映射、台账和全部单元发布。
2. 以相同流程完成第 3 部分。
3. 以相同流程完成第 4 部分。
4. 以相同流程完成第 5 部分。
5. 审核第 6 部分，形成明确的“可独立发布”题号清单；只发布该清单中的题。
6. 运行跨部分完整性检查、浏览器验收与最终报告。

每一批都先完成台账校验，再写入 `published: true`；未核对数据不得出现在读者可见的章节列表中。

## 验收标准

- 每个发布单元具有永久单元 ID，题目 ID 在所属部分内唯一且连续。
- 每个发布题目都有题页、规则页、答案页和已核对的原书答案、解析、译文。
- 构建器可从清单重建全部阅读器 JSON 与 Markdown 单元。
- 自动化测试覆盖每部分的完整题号范围、台账一致性、进度迁移、答案默认隐藏、滚动位置保持和静态资源 MIME 类型。
- 浏览器抽查每个部分至少一个首单元和末单元，包含一次错误作答、解析展开和刷新后的作答状态保留。
- 最终报告将列出发布范围、未发布的 `needs_review` 题目（如有）与验证命令结果。
