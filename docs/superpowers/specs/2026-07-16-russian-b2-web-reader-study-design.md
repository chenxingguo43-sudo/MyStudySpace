# 俄语 B2 网页阅读器主学习端：设计规范

**日期：** 2026-07-16

**状态：** 用户已确认视觉方向，等待书面规范复核

**替代：** `2026-07-15-russian-b2-replica-study-book-design.md` 中的 Obsidian 主学习端设计

## 1. 产品定位

`reader.html` 是俄语 B2 教材的主要学习入口，负责书架、章节导航、刷题、答案展开、逐题解析、原书页对照、查词、错题和学习进度。Obsidian 不再承担主要阅读和刷题体验，只负责保存原版 PDF、原始页图、OCR、人工校对记录、可搜索 Markdown、范围地图和质量报告。

旧目录 `D:\MyStudySpace\俄语资料库\俄语B2 全模块 Markdown版` 保持不变，只作为 OCR 对照材料。原版 `E:\Desktop\俄语B2.pdf` 仍是事实依据。

## 2. 成功标准

- 用户可在现有阅读器书架中进入“俄语 B2 全模块”，不需要打开 Obsidian 才能学习。
- 语法题以 8–12 题短单元呈现；题干和选项默认可见，答案与解析默认隐藏。
- 用户先选择 A/Б/В/Г，再确认答案；解析不会自动展开，必须由用户主动查看。
- 每题分别显示原书答案、原书依据、AI 参考解析和易错点，来源不会混淆。
- 桌面端题目为视觉主位，右侧可查看相关原书扫描页；窄屏下原书页按需展开且不产生横向滚动。
- 单词点查、主题、字号、书签、章节导航等现有阅读器能力保持可用。
- 错题和进度持久化；刷新或重新打开页面后不丢失。
- Obsidian 中仍可全文搜索、核对原书页和追溯每个学习单元，但不要求在 Obsidian 中完成互动学习。
- 第一批只交付并验证题目 1–10；试点未通过，不批量制作全书。

## 3. 总体架构

```text
原版 PDF / 190 张原始 JPEG
              │
              ▼
Obsidian 资料仓库中的规范化教材数据（唯一人工维护源）
              │
       自动生成与校验
       ┌──────┴─────────┐
       ▼                ▼
网页 JSON + WebP 页图   Obsidian Markdown 归档
       │                │
       ▼                ▼
reader.html 主动学习    搜索、核对、长期保存
```

禁止手工维护网页题库和 Markdown 两份内容。人工只修改规范化教材数据；构建脚本生成两端输出，并验证答案、页码和题号一致性。

## 5. 阅读器适配

### 5.1 通用教材加载

当前 `fetchChapter()` 以 `bookId === 'reading_speaking'` 判断教材，必须改成由 `data/textbook/index.json` 中的 `kind`、`dir` 和 `chapterPath` 决定数据目录。新增教材不得再增加新的硬编码 ID 分支。

书目条目至少包含：

```json
{
  "id": "russian_b2",
  "kind": "textbook",
  "format": "quiz-first",
  "title": "俄语 B2 全模块",
  "direction": "ru→cn",
  "chapters": 1,
  "dir": "russian_b2",
  "description": "原书对照、逐题解析与错题复习"
}
```

### 5.2 内容类型

阅读器保留现有小说和阅读教材渲染流程，并新增 `format: "quiz-first"`。该类型不要求先显示长篇原文，页面主体直接进入题组；规则说明和原书页作为辅助信息。

章节 JSON 的最小结构：

```json
{
  "index": 0,
  "title": "名词与形容词接格（题 1–10）",
  "module": "语法词汇",
  "format": "quiz-first",
  "sourcePages": {
    "questions": [18, 19],
    "rules": [24],
    "answers": [25, 26, 27]
  },
  "exercises": []
}
```

每题至少包含：

```json
{
  "id": "Q001",
  "type": "single-choice",
  "question": "...",
  "options": [
    {"key": "А", "text": "..."},
    {"key": "Б", "text": "..."},
    {"key": "В", "text": "..."},
    {"key": "Г", "text": "..."}
  ],
  "answer": "В",
  "sourceAnswer": "В",
  "sourceEvidence": "原书规则或答案说明",
  "referenceExplanation": "AI 辅助解析，待人工复核",
  "pitfalls": ["干扰项为什么不成立"],
  "questionPages": [18],
  "answerPages": [25],
  "reviewStatus": "verified"
}
```

`answer` 与 `sourceAnswer` 不一致时构建失败。未经页图核对的题目必须使用 `reviewStatus: "needs_review"`，页面也要显示该状态。

## 6. 刷题交互合同

每题执行以下状态流程：

```text
未选择 → 已选择 → 确认答案 → 显示正确/错误 → 主动展开解析
```

- A/Б/В/Г 使用真实单选控件，不使用任务复选框，也不只依赖卡片点击。
- 未选择选项时，“确认答案”不可用。
- 确认后锁定本次选择并显示正确或错误；不能立即覆盖原选择。
- “查看答案与解析”在确认后可用，但默认保持收起。
- 展开区按固定顺序显示：原书答案 → 原书依据 → AI 参考解析 → 易错点 → 对应原书页。
- AI 内容必须带 `参考解析（AI，待复核）` 标签，不能冒充原书解释。
- 错题可标记“加入复习”；再次作答记录新尝试，不删除历史错误。
- 章节不能因滚动到底部自动判定完成。完成条件为：全部题目已确认，或用户主动点击“结束本单元”。

## 7. 页面布局

### 7.1 桌面端（建议 ≥960px）

- 左侧 60–65%：题组、选项、确认按钮和折叠解析。
- 右侧 35–40%：原书扫描页查看器，支持题目页、规则页和答案页切换。
- 用户拖动分隔线时沿用现有阅读器分栏能力，宽度偏好保存在本地。
- 原书面板不能遮挡答题按钮；关闭后题目区恢复全宽。

### 7.2 平板与窄屏

- 768–959px：原书面板可从右侧打开，默认关闭。
- <768px：单列；“查看原书”在当前题下方展开或进入全屏页图层。
- 底部章节导航不能覆盖题目、答案按钮或最后一段解析。
- 选项与主要按钮最小点击高度 44px；俄语题干建议不小于 18px，选项不小于 16px。

### 7.3 状态表达与可访问性

- 正确、错误、已加入复习不能只靠颜色，必须同时有文本或图形标记。
- 单选控件、确认按钮、解析按钮和页图切换均支持键盘焦点。
- 图标按钮必须提供可见标签或可访问名称。
- 当前浅色主题中的辅助文字需要提高对比度；答案长文使用分节、段距和列表，禁止挤成一整段。

## 8. 学习记录

使用版本化本地数据，例如 `rr_b2_progress_v1`，按书、章节和题号保存：

- 当前选择与提交结果；
- 尝试次数；
- 首次与最近一次答题时间；
- 是否正确；
- 是否加入复习；
- 单元完成状态和最后打开位置。

错题记录与现有阅读统计分开，避免修改旧数据格式。后续如需云同步，再通过现有学习舱同步层扩展；试点阶段不改云同步协议。

## 9. Obsidian 输出合同

生成的 Markdown 保留：题干、选项、页码链接、答案折叠、原书依据、AI 标签和 `needs_review` 状态。它用于搜索和核对，不模拟网页单选、自动判题或进度交互。

生成器必须保证网页 JSON 和 Markdown 具有相同题号、选项、答案和页码映射。任何差异都使验证失败。

## 10. 试点范围

第一批严格限定为“名词与形容词接格，题 1–10”：

- 题目：PDF 18–19；
- 规则：PDF 24；
- 答案与说明：PDF 25–27；
- 已核对答案序列：`В, В, Б, А, Г, Г, А, А, А, Б`。

试点必须同时产生网页章节、WebP 页图、Obsidian Markdown、范围地图和验证报告。

## 11. 验收场景

1. 从阅读器书架进入“俄语 B2 全模块”。
2. 打开题目 1–10，未作答时所有解析保持隐藏。
3. 选择一个选项并确认，验证正确/错误状态和键盘操作。
4. 主动展开 Q001 解析，检查四层来源标注。
5. 切换 PDF 18、24、25 页并检查清晰度、缩放和返回路径。
6. 刷新页面，确认作答和错题状态仍在。
7. 检查桌面暗色、桌面浅色、窄屏和移动端；不得有遮挡或横向溢出。
8. 打开生成的 Obsidian Markdown，确认题号、答案和页码与网页一致。
9. 运行来源、结构、答案、范围、HTML 可用性和 Markdown 一致性验证。

## 12. 现有阅读器必须修复的问题

- 练习展开时滚动到底部会提前弹出“本章读完”；语法章节必须改用题目完成条件。
- `toggleExercises()` 的箭头状态与展开/收起方向相反。
- `detailed_explanation` 当前可能显示为密集长段；必须按段落和小节渲染。
- 部分浅色主题辅助文字对比度不足。
- 顶部多个纯图标按钮需要可访问名称或可见标签。

这些修复仅作用于相关组件和 `quiz-first` 流程，不得破坏现有小说阅读、词态还原、查词、书签和阅读报告。

## 13. 非目标

- 试点阶段不批量生成 190 页全书。
- 不在浏览器中像素级重画扫描书；页图是视觉证据。
- 不把 AI 解释写成原书答案。
- 不在第一版实现账户系统、跨设备云同步、间隔重复算法或复杂成绩分析。
- 不重构与本项目无关的番茄钟、俄语知识库或统计页。

## 14. 交付顺序

1. 建立规范数据和生成/验证测试。
2. 提取试点页原始 JPEG，并生成网页 WebP。
3. 通用化阅读器教材加载，加入 `quiz-first` 渲染。
4. 实现真实单选、确认、解析折叠、错题和进度。
5. 接入原书页分栏与窄屏降级。
6. 生成 Obsidian Markdown 和范围地图。
7. 在真实浏览器中完成全部验收场景。
8. 用户确认试点后，才为全书制定批量计划。

## 15. 风险与约束

- PDF 是扫描件，OCR 不能作为事实依据；题目、答案和规则必须与页图核对。
- 网页发布页图会增加仓库或部署体积；使用 WebP 预览，原始 JPEG 保留在资料仓库。
- `reader.html` 是大型单文件，修改必须局部化，并用回归检查保护现有阅读功能。
- 本地存储可能被浏览器清除；试点只承诺同一浏览器内持久化，后续再设计导出或同步。
- 当前工作区存在与本项目无关的已暂存和未跟踪文件；任何提交必须使用显式路径，禁止混入其他项目内容。
