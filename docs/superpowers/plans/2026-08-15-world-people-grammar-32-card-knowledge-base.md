# 《В мире людей - 语法词汇》32 张知识点卡与专属知识库实施方案

**日期：** 2026-08-15  
**状态：** 两张样板已实现，等待实学验收  
**项目入口：** Reader 书架中的 `В мире людей - 语法词汇`  
**内部书籍 ID：** `zlatoust_grammar`  
**实施范围：** 5 章、32 张知识点学习页、每卡思维导图、Obsidian 专属知识库、全书知识图谱  
**明确不包含：** 阅读口语、听力口语、写作口语、模拟考试、Android、正式后端

## 1. 目标和成功标准

本项目不是把原书重新抄一遍，也不是为所有 B2 教材建立通用模板。

原书的作用是确定知识点范围、基础规则、例句和正式练习；最终教学内容允许在此基础上加入可靠的 AI 教学补充。知识点卡 1.1 的价值不在于固定四段式，而在于它已经加入了经过用户调试的老师式讲解：大白话解释、判断步骤、正反例、常见误区、随堂题和反馈。

项目完成后应达到：

1. 32 张卡全部使用统一的新版教学外壳和与 1.1 相同的树形思维导图；阶段和树枝数量可以按知识点变化，但树形结构不变。
2. 每张卡可以从头学到尾，不依赖外部 AI 临时解释专业术语或补做题步骤。
3. 每张卡的导图均以一个中心问题向各学习阶段分枝；每枝固定呈现“识别要点、核心规则、例句、易错陷阱”，不是把四段文字换成四个框。
4. 32 张卡进入现有 `俄语笔记库`，形成可筛选、可链接、可离线复习的专属知识库。
5. 全书具有一张 5 章、32 卡和核心概念组成的 Obsidian Canvas 总图，并形成原生双向链接图谱。
6. Reader 仍是正式练习和学习进度的唯一权威来源，不创建第二套答题记录。
7. 不修改正式题 ID、题面、答案、映射和现有 localStorage 键。

## 3. 内容分层和编辑边界

### 3.1 三层内容

| 层 | 内容 | 本项目处理方式 |
| --- | --- | --- |
| 原书来源层 | `sourceRule`、`sourceEvidence`、原书例句、页码、正式题 | 保留现有内容与风险标记；不逐页重做 OCR，不冒充已人工校对 |
| AI 教学层 | 大白话解释、标准语法补充、自编例句、对比、判断路线、误区、反馈 | 本项目核心改写对象；允许超过原书讲解深度，但必须准确且标识清楚 |
| 学习记录层 | 随堂题状态、阶段复习标记、正式题记录、掌握状态 | 继续复用现有 Reader 数据；只增加非破坏性进度快照导出 |

### 3.2 AI 教学补充规则

AI 可以补充：

- 可靠的标准俄语语法解释；
- 原书没有说透的判断步骤和适用边界；
- 帮助理解的自编最小对比例句；
- 常见误判、反例和失效条件；
- 诊断题、随堂题、同类再练和迁移任务；
- 跨 stage、跨卡片的概念联系。

AI 不可以：

- 把补充规则标成 `source-rule` 或 `source-example`；
- 修改正式题答案来迁就讲解；
- 使用“永远、一律、所有情况”之类无边界绝对表述；
- 为原书没有覆盖的内容伪造页码或原书引文；
- 将不确定内容写成确定事实。

新增教学内容统一使用 `learning-note`；引用外部资料时使用 `external-note` 并保留来源与适用边界。

## 4. 目标数据契约

### 4.1 新版教学外壳开关

每张完成升级的学习页增加：

```json
{
  "teachingLayoutVersion": 2
}
```

Reader 以该字段决定是否使用新版教学渲染，不再硬编码 `sectionId === '1.1'`。字段缺失时继续使用旧版渲染，保证分批实施期间兼容未升级卡片。

### 4.2 通用卡内树形思维导图

每张升级卡使用 1.1 已验证的 `mindMap` 契约，不再新增 `conceptMap`、坐标轴图、流程图或其他专用图形。根节点用一句做题时优先要问的问题组织全页；必要时用 `mindMapRootLines` 调整根节点的两行短提示，例如 1.1 的“空格 / 做什么”、1.4.1 的“先看 / 时态”。

```json
{
  "mindMapMode": "retrieval",
  "mindMapRootLines": ["先看", "什么"],
  "mindMapQuestion": "做题时首先要判断什么？",
  "mindMapIntro": "先从中心问题出发，再进入对应学习阶段。",
  "mindMap": [
    {
      "id": "stage-example",
      "label": "一个判断分枝",
      "recognize": "识别要点：先问什么？",
      "rule": "核心规则：怎样判断？",
      "example": "例句：俄语例句 / 中文提示",
      "trap": "易错陷阱：不要把什么当成自动答案。"
    }
  ]
}
```

每个分枝的 `id` 必须等于一个稳定的 `stageId`。点击分枝、识别要点、规则、例句或陷阱时，页面跳到该阶段的完整老师讲解、随堂题和正式题入口，但不得改变学习完成状态。分枝数量随真实知识结构调整，不要求所有卡恰好四枝或五枝；四个学习维度不可缺少。

### 4.3 全书知识图谱清单

新增：

```text
data/textbook/zlatoust_grammar/theory/knowledge-graph.json
```

该文件只维护跨卡片关系和共享概念，不复制 32 张卡的正文。结构包含：

- `concepts[]`：核心概念节点；
- `sectionRelations[]`：卡片之间的关系；
- `conceptRelations[]`：卡片与核心概念之间的关系；
- `learningOrder[]`：推荐学习顺序。

跨卡关系只允许：

- `prerequisite`：先学；
- `part-of`：组成；
- `shared-concept`：共同概念；
- `contrast`：互为对比；
- `confusable`：容易混淆。

每条关系必须包含 `reason`。共享概念至少连接两张卡才允许成为总图节点，避免总图被一次性小词淹没。

每批开始前先为卡片标注 `直接升级 / 调整结构 / 复杂单独设计`，但所有卡最终都必须达到相同教学质量。

#### 每张卡的制作流程

1. 读取现有 learning page、rule unit、关联正式题和风险记录。
2. 用一句大白话写清“这张卡到底帮我判断什么”。
3. 重组 stage，使每个 stage 只解决一个清楚问题；保留现有稳定 ID，确需改结构时增加兼容映射。
4. 补足老师解释：术语定义、判断步骤、适用边界、最小正反例。
5. 审查每条 `signals`：必须同时说明何时有效和何时失效。
6. 审查每条 `commonErrors`：必须包含错误原因和正确做法。
7. 审查随堂题：选项必须只测试当前判断点，反馈必须指出具体误判。
8. 设计卡内 `mindMap` 树枝：每枝对应一个 stage，并补齐识别要点、核心规则、例句和易错陷阱。
9. 设置 `teachingLayoutVersion: 2`。
10. 运行卡片校验、专项测试和代表性浏览器检查。

#### 每批退出条件

- 5 张卡全部能独立走通“理解 → 判断 → 练习 → 反馈”。
- AI 补充与原书层标识清楚。
- 每张 `mindMap` 的根节点、树枝和四类行项目均完整，且每个 stage 锚点可点击跳转。
- 正式题 ID、答案、映射和进度键无变化。
- 不要求用户逐批全部实学；自动检查通过后继续，最终由用户抽样验收。

### Phase 5：构建全书知识图谱

#### Canvas 总图

`02-全书知识图谱.canvas` 使用：

- 5 个章节 group；
- 32 个知识点 file node；
- 仅为连接两张及以上卡片的概念创建核心概念 node；
- 有标签的关系边；
- 推荐学习顺序使用方向箭头；
- 对比、易混和共享概念使用不同颜色，但不只依赖颜色表达含义。

布局采用确定性分章网格，生成脚本多次运行时节点不会随机跳位。用户以后手工移动过的节点不在自动重建时保留；因此正式生成前先在脚本中稳定布局，发布后默认只重建受管理的数据内容，不无条件覆盖用户手调 Canvas。

#### Obsidian 原生图谱

每篇知识点笔记都写入真实 `[[wikilink]]`，使 Graph View 能自动形成：

- 章节 → 卡片；
- 卡片 → 核心概念；
- 前置卡 → 后续卡；
- 易混卡 ↔ 易混卡；
- 对比卡 ↔ 对比卡。

Canvas 负责可控布局，Graph View 负责动态浏览，两者来自同一份 `knowledge-graph.json`。
