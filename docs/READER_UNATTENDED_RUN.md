# Reader 无人值守运行

双击项目根目录的 `run-reader-production-unattended.bat`，即可对当前 Reader 教材生产队列执行自动运行。

脚本会先刷新来源、恢复过期任务并做检查，然后按配置批量调用本机 Codex CLI：Luna 负责初稿，Sol 负责独立审查，主机负责校验和写回。它同时处理 B2 六个语法分部的逐题解析和知识点卡片。网络传输失败或 Codex 进程异常时，默认自动重试 3 次；每次重试都从已经保存的状态继续，不会重新生成已经完成的任务。

答案矛盾、来源不足、选项错位和质量检查失败不会被当成网络故障。每批先由 Luna 生成、Sol 检查；未通过的题允许 Luna 再修改一次，仍未通过才由 Sol 修改并再次独立检查。最后仍不合格的题保留为阻塞，不会写进教材，其余题可继续。

连续两批没有任何题通过时，脚本停止领取新题，避免继续无效花费。已经开始的模型调用会收尾并保留草稿，不再发起后续修改或检查。全部可处理题跑完后，只要还有阻塞题，也不会报告“全部完成”。每批写入后的自动检查失败则撤回该批写入并停止，其余在做的批次保留草稿退回待处理。

默认运行配置：

- profile：`russian-b2-grammar`
- preset：`codex-luna-sol-b2-grammar`
- 队列：330 道语法题 + 34 张知识点卡片
- 每批：2 个任务，最多两批同时做；写入教材和检查文件仍逐批进行
- 每批完整保留 Luna 初稿、Sol 检查、必要时 Luna 修改、Sol 疑难修改与独立复查
- 调用方式：本机 Codex CLI，不调用浏览器 AI
- 完整句与中文翻译、判断过程、逐项分析仍保留；按解释是否充分检查，不强行凑字数
- 检查时省略完全相同的兼容存储副本，实际内容冲突仍保留供检查
- 日志：`.reader-pipeline/russian-b2-grammar/production/unattended-*.log`
- 每批进度：`.reader-pipeline/russian-b2-grammar/production/progress.json`
- 单次调用耗时与用量：`.reader-pipeline/russian-b2-grammar/production/invocations-*.jsonl`
- 本轮退出报告：`.reader-pipeline/russian-b2-grammar/production/last-run.json`

`progress.json` 在每批保存后及本轮退出时更新，不表示程序此刻一定在运行。`batches` 是已领取的批数，`batchesFinished` 是已通过文件检查并保存的批数。`elapsedMs` 是本轮实际经过的时间；退出报告的 `modelElapsedMs` 是模型调用耗时相加，两批同时工作时它可能大于实际等待时间。`last-run.json` 是最近退出的一轮，可能早于当前运行；看状态时须同时核对运行标识、时间和进程。调用日志中的 token 是程序读到的模型用量，不等于账单金额，也可能不含被强行中止的请求。

也可以在 PowerShell 中指定参数，例如把网络重试次数改为 5：

```powershell
./scripts/run-reader-production-unattended.ps1 -MaxRetries 5 -RetryDelaySeconds 60
```

如需暂停，先让当前批次完成保存：

```powershell
node scripts/reader-production.js pause russian-b2-grammar
```

暂停请求不会中断正在进行的模型调用。已经领取的最多两批会完成检查和保存，程序不再领取新题。继续时先取消暂停标记，再双击入口：

```powershell
node scripts/reader-production.js unpause russian-b2-grammar
```

不要同时启动两份。这个入口是本机后台运行程序，不是关机后仍能运行的云服务；电脑必须开机、联网且不进入睡眠。无人值守不等于无条件放行，阻塞题需要核查后单独重试。

## 同日两批同时工作验证

在完整保留原有生成、修改和独立检查次数的条件下，新增 `parallelBatches: 2`。模型同时处理不同题目，各自只保存草稿；主程序逐批写入和检查。慢题不会阻止另一个位置领取新题。发生共享检查错误时，先前通过的批次保留，出错批次撤回，其余草稿保存后退回待做。已运行的长任务不会因领取时间过期而被另一批重复领取。

22:16:34 至 22:22:29 的 Q035-Q038 试跑：4 道全通过，2 批均经过文件检查，实际用时 354.831 秒（5.91 分钟），记录用量 96,206 token。两批都发生了修改及再次独立检查，没有跳过质量步骤。

本次 8 个模型调用的耗时相加为 564.596 秒（9.41 分钟），与实际经过的时间相比，重叠等待减少约 37%，同一批调用对应约 1.59 倍速度。这是同一次运行的时间拆分，不是重新用旧方式跑了一遍的对照实验，也不保证全书每批都有相同提升。并行本身不减少单题 token。
