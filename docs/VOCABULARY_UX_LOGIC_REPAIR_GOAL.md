## 3. 产品决策

### 3.1 刷词模式

刷词模式是“快速主动回忆 + 当场回炉”，不是只浏览一遍。

每张卡的正确流程：

1. 正面展示俄语词和重音题。
2. 点击卡片、空格或“认识”第一次操作，只展示答案，不计为掌握。
3. 用户确认“认识”后，该词本轮标记为 known，只计数一次。
4. 用户选择“不认识”后，展示答案并将该词安排在约 8 张之后回炉。
5. 回炉词再次“不认识”时继续排队，不设放弃阈值。
6. 只有全部唯一词条都确认“认识”后，才能出现“全部掌握”和 100%。

刷词模式暂时保留两个按钮：

- 不认识：展示答案；确认后进入回炉队列。
- 认识：第一次展示答案，第二次确认认识并前进。

必须避免一次用户动作执行两次状态迁移。一个词从不认识改为认识时，也只能使已处理/掌握计数增加一次。

### 3.2 普通复习模式

普通复习模式继续使用三个评分：不认识、模糊、认识，并保留当前会话内回炉。

长期调度必须以本轮最差表现为依据：到期旧词如果先答错、随后回炉答对，不能按“全程一次答对”的方式扩大原有间隔。至少应重置为短间隔或 relearning 状态。

困难词可以结束当轮重复，但统计上必须互斥：一张卡不能同时算“普通通过”“回炉通过”和“困难词”。

## 4. 已确认问题

### P0：刷词状态机与学习结果

1. `rateBrush()` 重复定义，后一个覆盖前一个，导致回炉实现成为死代码。
2. 连续把全部词标记为“不认识”后，系统仍显示“全部掌握、掌握率 100%”。
3. “不认识”没有真正进入 `brushRetryQueue`，`brushRetried` 和回炉统计始终为 0。
4. 不认识后点击“确认认识”需要额外多点一次，按钮文案与实际状态不一致。
5. 同一个词可同时触发 `brushAnswered++` 两次，进度可能超过总数，剩余数可能变成负数。
6. `undoBrushRate()` 没有完整恢复 `brushAnswered`、`brushUnknown`、答案可见状态和当前队列位置。
7. 刷词空筛选结果错误进入完成页，并显示“0 个词全部掌握、100%”。
8. 刷词完成页固定写死 100%，没有验证 known 数是否等于总数。

### P0：刷词更多菜单

1. 刷词菜单已经显示，但收藏、跳过、标记问题仍调用普通模式的 `renderCard()`。
2. 实测刷词中点击收藏后，当前卡组消失并显示“没有符合条件的词条”，顶部仍停留在刷词模式。
3. `toggleFav()`、`toggleSkip()`、`reportCard()` 必须根据 `currentMode` 调用正确渲染器并维护正确队列。
4. 跳过和标记问题后必须从当前刷词队列安全移除，不能误计为掌握，也不能让会话卡死。

### P1：筛选和数据接入

1. 词性筛选值使用 `adj` / `adv`，数据实际使用 `adjective` / `adverb`。
2. 当前数据中 649 个形容词和 182 个副词选择后均返回 0 条。
3. “功能词”当前只匹配 `particle`，需要明确是否应包括 pronoun、numeral、preposition、conjunction、interjection。
4. 空筛选结果必须显示真实空状态，不能显示完成或 100%。
5. `loadVocabulary()` 没有加载 `/api/novel-vocab-list`，阅读器保存的新小说词可能不能及时进入生词本。
6. 小说词的 `sourceSentenceRu` / `sourceSentenceZh` 应转换为卡片例句并保留来源。
7. 数据中存在至少一个空释义词条，答案面必须有可理解的缺失状态，不能呈现空白答案。

### P1：普通复习与统计

1. `passed=true` 的困难词同时被计入通过、回炉后通过和困难词。
2. 顶栏使用 `getPassedCount() + getLeechCountInSession()`，可能重复计数并使进度超过总数。
3. `deck.length + delayedQueue` 混合唯一卡数与尝试次数，总数会在学习中变化。
4. `getDelayedCount()` 排除已经 ready 但尚未抽出的卡，导致“回炉中”瞬间减少。
5. 完成页“共复习 N 个词条”实际使用评分次数，不是唯一词条数。
6. 到期旧词先错后对时，最终评分 5 可能基于旧 interval 继续放大间隔。
7. 普通模式的收藏、错题等专用模式会再次经过到期过滤，可能导致用户收藏的未到期词完全不显示。
8. 设置保存时直接 `applyFilters()`，会无提示重置当前学习会话。

### P1：日期、持久化与同步

1. `getTodayKey()` 使用 UTC 日期；中国时区 00:00-07:59 会被算到前一天。
2. 连续天数、今日新卡、导出文件名、明日预计复习和服务器同步必须统一使用本地日期键。
3. 刷词中新卡检查发生在 `saveRecord()` 之后，因此 `incNewCardsToday()` 永远不会执行。
4. 导入只检查 `records` 是否存在，没有校验 records、extras、settings 的类型与字段。
5. `getExtras()` 对缺少 `fav` / `skip` / `report` 的旧数据缺乏归一化，后续 `.indexOf()` 可能报错。
6. 导入、保存和 localStorage 写入失败需要内联错误提示，避免只有 `alert()` 或静默失败。

### P1：桌面与移动端布局

1. `adjustCardHeight()` 按背面完整内容设置桌面卡片最小高度，抵消内部滚动。
2. 在 1280x720 实测中，长卡片高约 770px，工具栏顶部约 859px，评分按钮顶部约 905px，首屏完全看不到操作。
3. 桌面卡片也应受视口高度约束，长答案在 `.card-back` 内滚动。
4. 手机底部评分栏与备份提醒都固定在 `bottom:0`；备份提醒 z-index 更高，会覆盖评分按钮。
5. 横屏 Android 宽度通常超过 600px，当前不会获得完整移动端触控尺寸和固定底栏。
6. 横屏规则只压缩卡片，没有统一 44-48px 触控尺寸、安全区和底部操作逻辑。
7. 控制抽屉、更多菜单、Toast、设置弹窗、备份提醒和固定评分栏必须建立明确的 z-index 层级。

### P2：音频、背景和可访问性

1. 自动发音使用多个未保存句柄的 `setTimeout()`；快速切卡时旧词仍会延迟播放并打断当前词。
2. 卡片初次渲染和显示答案都可能调用自动播放，设置文案“翻卡时自动播放”与实际行为不一致。
3. 音频 manifest 尚未加载完成时，首张卡可能错误降级到浏览器 TTS。
4. Android WebView 的自动播放和 `speechSynthesis` 能力不稳定，失败时不能阻断学习流程。
5. 手机上传高分辨率背景图后直接把完整 Data URL 写入 localStorage，可能触发容量异常。
6. 上传前应校验类型、尺寸并压缩；写入失败要提示用户。
7. 模式切换清除的是 `mode-active`，顶部快捷按钮使用 `active`，可能出现多个模式同时高亮。
8. 设置弹窗缺少 `role="dialog"`、`aria-modal`、初始焦点、Esc 关闭和焦点约束。
9. 卡片、语法折叠和例句折叠使用可点击 `div`，缺少键盘和屏幕阅读器语义。
10. 更多按钮缺少 `aria-expanded` / `aria-controls`，菜单缺少菜单语义。

## 5. 实施顺序

### 阶段 A：先建立行为测试

不得只写 `html.includes()` 类型的静态断言。至少增加可执行状态机测试，覆盖：

1. 刷词一次认识。
2. 刷词不认识后回炉。
3. 同一个词多次不认识后仍继续回炉。
4. 不认识后最终认识，只增加一次掌握数。
5. 全部不认识时不能完成。
6. 空筛选显示空状态。
7. 撤销恢复卡片、队列、统计和长期记录。
8. 普通复习先错后对的长期 interval。
9. 困难词统计互斥。
10. 本地日期在 Asia/Shanghai 凌晨边界正确。

如果单体 HTML 难以测试，可以只提取无 DOM 的纯调度函数到现有 `js/` 目录；不要把整页迁移框架，也不要进行无关重构。

### 阶段 B：修复刷词核心

1. 删除重复 `rateBrush()`，只保留一个权威实现。
2. 明确唯一状态来源，避免 `flipped`、`brushAnswerVisible`、`brushPendingKnown` 相互矛盾。
3. 恢复“不认识 -> 约 8 张后回炉 -> 直到认识”的循环。
4. 进度定义为 `knownUnique / totalUnique`。
5. 分开显示掌握、排队、未首次出现，不使用含糊的 `brushAnswered`。
6. 完成条件必须是所有有效词条均在 `brushKnown` 中。
7. 修复撤销和“只刷回炉词”。

### 阶段 C：修复菜单、筛选和阅读器接入

1. 让收藏、跳过、标记问题调用模式感知的推进函数。
2. 修正 adjective / adverb 映射和功能词分类。
3. 恢复 `/api/novel-vocab-list` 加载和来源例句映射。
4. 增加真实的无匹配、无释义、加载失败状态。

### 阶段 D：修复普通复习和长期调度

1. 统一唯一卡数、尝试次数、通过、回炉和困难词定义。
2. 修复先错后对的长期调度。
3. 修复今日新卡计数和本地日期。
4. 让设置保存尽量不中断会话；确需重建卡组时先提示。
5. 对导入数据做 schema 归一化和兼容。

### 阶段 E：修复响应式与 Android 风险

1. 桌面和手机卡片都采用稳定视口约束，背面内容内部滚动。
2. 解决备份提醒与评分栏覆盖。
3. 增加宽屏横屏手机条件，而不是只依赖 `max-width:600px`。
4. 校验 360x800、390x844、412x915、844x390、1280x720、1440x900。
5. 每个视口检查：横向溢出、文字遮挡、固定栏遮挡、滚动可达、44px 触控目标、安全区。

### 阶段 F：音频、上传和可访问性

1. 为自动播放任务维护可取消的 timer/token，切卡立即取消旧任务。
2. 明确自动播放只发生在哪个状态。
3. 上传背景前压缩并捕获容量异常。
4. 补齐 dialog、菜单、折叠控件和图标按钮语义。

## 6. 必须通过的验收场景

### 刷词模式

- 仅有 3 张卡，三张全部点不认识：不得出现完成页；三张都必须进入回炉。
- 一张卡不认识两次、第三次认识：完成后显示回炉后通过 1、一次过 0、总回炉 2。
- 一张卡首次认识：必须先展示答案，再确认；只产生一次掌握和一次长期记录更新。
- 不认识后点击“下一张”不能丢卡。
- 收藏当前卡后继续留在刷词模式且推进逻辑正常。
- 跳过/问题卡不计为掌握，但会安全离开当前会话。
- 撤销后回到刚才的卡，统计和队列完全恢复。
- known 数小于总数时，任何路径都不能显示 100%。

### 普通复习

- 正面方向键只显示答案，不评分。
- 到期旧词先不认识、回炉后认识：长期 interval 不得按一次答对扩大。
- 困难词只能归入一个统计类别。
- 顶部进度不得超过 100%，总数学习中不得无故增加。
- 今日新卡达到上限后不再引入新卡，但到期复习仍可继续。

### 筛选与数据

- 形容词筛选结果约为数据中的 adjective 条目，而不是 0。
- 副词筛选结果约为 adverb 条目，而不是 0。
- 搜索和筛选无结果时显示“没有符合条件的词条”，不显示完成。
- 阅读器新保存的小说词无需重建整个词库即可出现在生词本。
- 空释义词显示“释义待补充”并可标记问题。

### 移动端和桌面端

- 1280x720 首屏可看到卡片主要内容、工具栏和评分操作。
- 手机竖屏底部评分栏不遮挡卡片内容、Toast 或备份提醒。
- 844x390 横屏按钮仍满足触控尺寸，卡片背面可滚动。
- 打开软键盘搜索时，控制抽屉仍能滚动并能关闭。
- 设置弹窗在小屏可滚动，保存和取消始终可达。

### 音频和背景

- 快速连续切换三张卡，只允许当前词继续播放。
- 自动播放关闭后，任何显示或翻卡都不得自动发音。
- 大图上传失败或压缩失败时出现可理解提示，学习数据不受影响。
