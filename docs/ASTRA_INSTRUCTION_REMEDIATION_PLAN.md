# Astra 指令与 Skill 整改计划

状态：已执行；保留为整改依据与验收记录  
日期：2026-09-06  
适用范围：当前实际可见的 `AGENTS.md`、用户级与项目级 `SKILL.md`、Skill 启用设置及直接关联说明文件

## 1. 为什么要整改

OpenAI 对 GPT-6 Astra 的最新指导指出：Astra 更能遵守长指令，也更容易被文件中的含糊、冲突和绝对化要求影响。结果可能是反复询问、过早停工、执行无关流程，或对小改动做过多检查。

本次整改不追求把文件机械缩短，而是让每条规则都回答四个问题：

1. 什么时候适用；
2. 什么时候不适用；
3. 与用户当轮要求冲突时听谁的；
4. 做到什么程度可以继续或结束。

官方参考：

- [GPT-6 Astra model guidance](https://developers.openai.com/api/docs/guides/latest-model)
- [Agent Skills](https://developers.openai.com/codex/skills)
- [Custom instructions with AGENTS.md](https://developers.openai.com/codex/guides/agents-md)

## 2. 整改目标

整改完成后，应达到以下结果：

- 用户当轮明确要求始终优先于 Skill 的默认做法；
- 审查、解释或引用一个 Skill，不会被误认为要执行该 Skill；
- 已经获得的授权可以沿用，不会在每一步重复询问；
- 只有真正会改变结果的缺失信息才需要询问；
- 小改动只做与它相称的检查，大改动才扩大检查范围；
- 本地任务不会无条件发送给网页 AI；
- 长任务可以继续完成，不依赖用户反复发送“继续”；
- 同名 Skill 只保留一个明确入口，历史版本不会参与自动选择；
- Reader 的首次试做验收与已验收后的批量续做分开处理；
- 安全、教材原文、学习进度和用户现有改动继续受到保护。

- 浏览器本地学习进度不能因改动丢失；
- 真正影响页面外观或操作流程的改动要检查电脑和手机显示；
- 批量教材生产要能保存进度、恢复运行，并在共享问题出现时及时停止。

## 5. 统一改写原则

所有目标文件使用同一套原则：

1. 用户当轮明确要求优先于 Skill；Skill 只补充用户没有说明的做法。
2. “审查、解释、引用、比较、排错”不等于“调用或执行”。
3. 用户已经授权的范围持续有效，除非后续动作明显超出范围或不可轻易恢复。
4. 只在答案会明显改变结果时询问；能从当前文件和上下文查到的信息由 Agent 自行查清。
5. 测试和检查按影响范围决定；相关检查通过后，不因没有新证据而重复扩大。
6. “必须、始终、绝不、每次、全部”只用于安全边界和确实没有例外的规则。
7. 每个停止条件必须同时写明恢复方法；不能只写“停止”。
8. 外部发送、登录、密钥、安装、覆盖、删除和发布必须有清楚的触发条件。
9. 一个 Skill 只负责一类工作；相邻 Skill 用明确的正面和反面例子分工。
10. 项目事实和个人偏好放在 `AGENTS.md`；偶尔使用的专用流程放在 Skill；确定的机械检查尽量交给程序。

## 6. 计划顺序

- 再次记录 `git status --short`；

### 阶段 1：加入共同总则

### 阶段 2：修复高风险触发

- 修正 AgentChat 两个 Skill 的“调用即发送”；

### 阶段 3：消除同名入口

- 保留正式版；
- 通过 Skill 设置关闭重复副本和历史版的自动选用；
- 必须保留用于复现的版本改为明确名称，并关闭自动调用；
- 不直接删除历史目录。

### 阶段 4：统一 Reader 生产规则

- 明确首次试做何时需要学习者验收；
- 把验收结果和适用范围写入可恢复状态；
- 已验收范围继续批量处理；
- 教材事实冲突、答案缺失、共同检查失败仍可阻止继续；
- 报告恢复命令，但不要求用户用“继续”来维持普通长任务。

### 阶段 5：整理设计类 Skill

- 先收窄触发说明；
- 再删除模拟执行和无条件视觉配方；
- 把互相冲突的风格规则改成按任务选择；
- 将大检查表拆成共同底线和按场景检查；
- 局部页面修改只读目标页面及直接共用内容。

### 阶段 6：复验

- 检查所有修改后的 Skill 格式；
- 使用正向、反向和容易混淆的请求测试触发；
- 使用小改动、长任务、只读审查、外部发送和 Reader 批量续做五类情境测试行为；
- 核对敏感信息、学习进度、用户改动和 Git 状态；
- 对确实改变主观体验的部分再请用户判断，不把所有客观检查都变成等待确认。

## 7. 优先级

### P0：开始整改前必须先保护

- 敏感信息不得进入快照、报告或外部 AI；
- 不得覆盖用户当前大量未提交改动；
- Reader 的原文、答案、题目编号和学习进度不得受损。

### P1：本轮整改应完成

- “读到 Skill 就必须执行”的冲突；
- 本地任务无条件发送外部 AI；
- 长任务要求用户反复发送“继续”；
- 已有授权仍重复确认；
- 同名 Skill 入口不清；
- 小改动被扩大为整站检查；
- Reader 已验收工作仍在每批停下来等待。

### P2：在 P1 稳定后处理

- 设计类 Skill 的风格配方过多；
- 为旧模型写的贬低性提醒和模拟随机流程；
- 检查表过长、重复和不适用项没有出口；
- Skill 制作规则默认面向弱模型和所有平台；
- 文案层面的重复和旧宿主名称。

## 8. 完成标准

全部满足以下条件才算整改完成：

1. 每个被改 Skill 都有修改前快照；
2. 所有 P1 问题均已修复或由用户明确保留；
3. 没有删除安全、教材和数据保护要求；
4. 同名 Skill 的自动入口已经唯一；
5. 只读审查不会执行被审查 Skill；
6. 用户已授权的普通任务不会在可继续时停下来等待；
7. 小改动不会触发全项目扫描或整套检查；
8. 本地内容不会在没有相应请求时发送到外部服务；
9. Reader 首次试做与已验收续做行为清楚且可恢复；
10. 静态检查、触发测试和关键情境测试通过；
11. 改动清单中没有敏感文件、临时文件或无关用户改动；
12. 未自动提交或上传。

## 9. 本计划不授权的事项

本文件只描述建议的整改工作。它本身不授权：

- 修改任何现有 `AGENTS.md` 或 `SKILL.md`；
- 关闭、移动或删除任何 Skill；
- 安装软件或登录外部服务；
