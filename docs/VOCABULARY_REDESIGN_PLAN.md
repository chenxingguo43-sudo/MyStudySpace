# Vocabulary 页面重构计划

状态：方案阶段，尚未开始页面实现
日期：2026-07-26
参考目录：`E:\Desktop\vocabulary的页面重构`
主文件：`vocabulary.html`

## 1. 目标

将现有 Vocabulary 页面重构为一套可在移动端和桌面端长期使用的词汇学习工作区。移动端以参考软件截图为主要视觉基准，桌面端保留同一套视觉语言，但使用全屏学习工作区，而不是把手机页面居中放大。

本次覆盖参考截图中的全部页面状态：

- 词书/书架入口
- 极速刷词首页
- 刷词卡正面
- 刷词卡答案面
- 单词详情
- 单词小结列表
- 学习数据
- AI 问答弹层
- 重学确认弹层

页面内容继续使用项目现有俄语词库、例句、重音、掌握度和学习记录，不替换为英语数据。

## 2. 参考图提取结果

### 2.1 整体视觉

- 背景是浅薄荷色到乳白色的纵向渐变，顶部更有颜色，内容区逐渐变白。
- 主色为明亮的青绿色，目标值约为 `#08C9A9`，用于进度、发音、主按钮和选中状态。
- 文字为近黑色，辅助文字为中灰色，避免大面积纯黑。
- 主容器以白色内容块为主，圆角约 28-32px，阴影非常柔和。
- 页面留白明显，信息通过字号、位置和细分割线组织，而不是大量标签和边框。
- 固定底部操作栏使用高触控尺寸按钮，手机安全区需要被计算在内。

### 2.2 刷词首页

- 顶部为轻量标题栏：退出/返回、页面标题、搜索或帮助入口。
- 中央展示当前词书、轮次、完成进度和当前数量。
- 刷词模式、乱序、收藏等选项使用独立的白色横向操作块。
- 最重要的动作是底部青绿色“开始刷词”按钮。

### 2.3 刷词卡正面

- 顶部显示模式标题和 `当前 / 总数`。
- 主卡为大面积白色圆角卡，后方可以有一层轻微错位的卡片阴影，表达卡组深度。
- 单词居中，字号大，重音/音标和发音按钮紧跟在单词下方。
- 收藏放在卡片右上角，难度或词书标签放在左上角。
- 正面只允许查看和翻面，不直接评分。
- 底部主操作是“下一個/先看答案”一类的单一操作，避免正面显示三种评分造成误判。

### 2.4 刷词卡答案面

- 保持与正面相同的白色卡片结构。
- 展示词性、中文释义、例句、来源和可折叠补充信息。
- 右侧保留发音动作，相关词和来源内容使用低对比度分割。
- 评分按钮放在底部：不认识、模糊/稍后、认识；移动端固定在底部，桌面端横向展开。
- 认识使用青绿色主按钮，不认识使用橙色文字/弱按钮，模糊使用灰色次按钮。

### 2.5 列表与详情

- 单词小结是纵向列表，每行包含单词、词性、释义和右侧发音按钮。
- 每行用细虚线分隔，不使用厚重卡片套卡片。
- 单词详情是开放的内容流，包含词条、音标、释义、例句、来源例句、提醒和笔记。
- 详情页可以有固定底部“下一个”按钮。

### 2.6 学习数据

- 顶部使用横向标签切换：今日成就、记忆曲线、学习进度、学习记录。
- 数据区以白底大块内容呈现，主色用于环形图、进度条和选中标签。
- 统计数字需要有清晰的主次层级，不能使用过多装饰性徽章。

### 2.7 AI 问答与弹层

- AI 问答使用接近全屏的白色圆角弹层，顶部有关闭、居中标题和“内容由 AI 生成”提示。
- 回答内容使用大字号、足够行高和较宽的段落间距。
- 底部提供相关追问和输入框，支持保存笔记、点赞和点踩。
- 重学确认使用居中的白色弹窗，背景遮罩压暗页面，选项为大尺寸白灰按钮，继续操作为青绿色主按钮。

## 3. 响应式策略

### 移动端

- 目标视口：`360x800`、`390x844`、`412x915`、`430x932`。
- 单列结构，左右安全边距 16-24px。
- 卡片高度由视口计算，不让底部评分栏遮挡答案内容。
- 所有主要按钮触控尺寸至少 44px，底部栏考虑 `env(safe-area-inset-bottom)`。
- 详情和答案内容在卡片内部滚动，页面整体不产生横向溢出。

### 桌面端

- 目标视口：`1280x720`、`1440x900`。
- 使用全屏工作区，不采用居中手机壳布局。
- 顶部工具栏横向铺满；中央主卡扩大到可用空间；底部操作栏横向展开。
- 详情、列表、统计等状态通过抽屉或全屏视图进入，不长期挤占刷词主卡。
- 主卡的阅读宽度保持受控，避免长句横向拉满屏幕。

## 4. 数据与逻辑边界

必须保持：

- `vocabulary-review-records`
- `vocabulary-extras`
- `vocabulary-settings`
- 现有词库加载和小说词汇接入
- 现有刷词回炉队列、评分、撤销、收藏、跳过和问题标记逻辑
- 现有音频优先级和 TTS 降级逻辑
- 现有测试能够继续运行

视觉重构不得重新实现评分状态机，不得改变 `rate()` 的产品语义，也不得恢复已经取消的 3D 翻卡效果。

## 5. AI 能力方向

AI 页面本次实现完整的前端交互和接口契约，但不把 API Key 或具体模型写入前端。

建议接口：

```text
POST /api/ai/ask
{
  "task": "vocabulary_explain",
  "word": "...",
  "question": "...",
  "context": {
    "meaning": "...",
    "examples": []
  }
}
```

未来可以复用同一服务层扩展：

- `vocabulary_explain`
- `speaking_practice`
- `writing_feedback`
- `dialogue_roleplay`

页面层应支持 loading、成功、失败、重试和保存笔记状态；后端未准备好时允许使用本地 mock 响应进行 UI 验证。

## 6. 非目标

- 本阶段不替换词库数据结构。
- 本阶段不迁移到 React、Vue 或其他框架。
- 本阶段不引入完整 FSRS 或替换现有调度算法。
- 本阶段不提交 `cloudsync-config.js` 或处理其凭据。
- 本阶段不自动 push。

## 7. 完成标准

- 移动端所有参考状态可进入、可返回、无横向溢出。
- 桌面端为全屏工作区，主卡、详情和底部操作在首屏可用。
- 刷词正面先看答案，答案面再评分，现有回炉逻辑不退化。
- 收藏、跳过、问题标记、设置、导入导出和音频保持可用。
- AI 问答页面具有完整交互状态，并使用明确的后端接口契约。
- 通过现有 vocabulary 测试和新增的状态机/响应式验收测试。
- 在目标视口完成截图检查后，才进入交付。
