# LLM 能力测试集 V1 使用指南

> 状态：测试集已设计，尚未运行。它用于选型，不代表任何候选模型已经通过。

## 1. 测试目标

验证候选 LLM 是否能在白夜俄语的单 Agent 架构中稳定完成：

- 理解中俄混合和双通道 ASR；
- 在转写冲突时区分可判定与不可判定情况；
- 不确定时诚实追问，不静默猜测；
- 遵守俄语朋友、耐心外教的回复长度和互动策略；
- 自适应提供关键词/句型支架；
- 不在日常会话中打断式纠错；
- 正确使用或不使用记忆；
- 输出可供字幕、分段 TTS、关键词和支架 UI 消费的结构化结果。

## 2. 测试集

固定用例位于：`data/llm-capability-test-v1.json`

共 12 条：

| 用例 | 核心能力 |
|---|---|
| LLM-01 | 普通俄语日常回复 |
| LLM-02 | 中俄混合表达 |
| LLM-03 | 中文导演指令/场景切换 |
| LLM-04 | 双通道结果一致但表述不同 |
| LLM-05 | 双通道关键地点冲突，必须澄清 |
| LLM-06 | 短回答后的一级支架 |
| LLM-07 | 连续卡住后的支架升级 |
| LLM-08 | 连续两轮过长后的强制缩短 |
| LLM-09 | 日常会话延后纠错 |
| LLM-10 | 不滥用无关记忆 |
| LLM-11 | 临时事实与记忆候选区分 |
| LLM-12 | 严格 JSON 输出契约 |

## 3. 候选对比的统一条件

每个候选必须使用完全相同的 system prompt、JSON Schema 和测试输入，并使用完全相同的：

- 测试用例；
- system prompt 版本；
- JSON schema 或等效结构化输出约束；
- temperature、top_p、最大输出 Token；
- 上下文与记忆；
- 超时、重试次数和网络环境。

每个 case 至少运行 3 次，不能只看一次成功结果。保留：

- 原始请求（脱敏）；
- 原始响应；
- HTTP 状态和错误；
- 首 Token 延迟、完整响应延迟；
- 输入/输出 Token；
- 重试次数；
- 解析后的结构化结果。

## 3.1 统一基线文件

- System prompt：`docs/llm-system-prompt-v1.md`（版本 `system-prompt-v1`）
- JSON Schema：`data/llm-output-schema-v1.json`（版本 `llm-output-schema-v1`）
- 测试输入：`data/llm-capability-test-v1.json`

每个 case 的 JSON 作为一次 user message 发送；`outputSchema` 只作为标识，不能让候选自行改变 schema。模型原始响应先按 UTF-8 文本保存，再进行 JSON 解析和 schema 校验。

## 3.2 统一运行参数（第一版基线）

在实际跑候选前固定并记录以下参数：

```json
{
  "temperature": 0.2,
  "top_p": 1,
  "max_output_tokens": 700,
  "stream": false,
  "requestTimeoutMs": 30000,
  "retries": 1
}
```

V1 先用 `stream:false` 验证严格 JSON 稳定性；供应商选定后再单独测试流式 JSON/文本的首 token 延迟，不混入本轮质量结论。

## 4. 评分维度

建议总分 100：

| 维度 | 分值 | 说明 |
|---|---:|---|
| 意图理解与事实保留 | 25 | 是否正确理解用户，不虚构事实 |
| 约束/陪练行为遵循 | 25 | 长度、追问、身份、纠错和支架 |
| 双通道 ASR 判断 | 15 | 一致时不乱澄清，冲突时不瞎猜 |
| 结构化输出稳定性 | 20 | JSON 合法、字段完整、TTS/字幕可用 |
| 回复自然度与学习价值 | 10 | 俄语自然、能推动用户继续说 |
| 记忆边界 | 5 | 相关才用，候选不冒充永久事实 |

另行记录性能指标，不用质量分掩盖性能问题：

- 首 Token 延迟 P50/P95；
- 完整响应延迟 P50/P95；
- JSON 解析成功率；
- 超时率、重试率、空回复率；
- 平均输入/输出 Token；
- 单轮估算成本。

## 5. 通过门槛（建议初版）

候选进入下一轮的最低条件：

- 12 条 case 的平均质量分 ≥ 80；
- LLM-05 不得自行选择北京或彼尔姆；
- LLM-08 不得继续输出长回复；
- LLM-12 三次运行全部是可解析 JSON；
- 所有 case 的结构化输出总体解析成功率 ≥ 95%；
- 不出现明显的隐性翻译、虚构用户事实或绕过单 Agent 架构的结果。

这只是进入下一轮的门槛，不等于最终生产选型。

## 6. 当前不测试的内容

- 不测试音频理解；ASR 已在独立基准中测试，LLM 接收的是两路文字和时间戳。
- 不测试 B2 正式评分；需要另建评分证据测试集。
- 不测试开放式工具调用；Phase 1 先不引入复杂 Agent 工具。
- 不把某个候选的宣传指标当作通过证据。


测试结束后再建立：
