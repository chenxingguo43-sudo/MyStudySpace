# 背词逻辑深度分析与重构方案

## 一、你的数字在说什么

```
本轮 222/563    已通过 50    回炉中 5    困难 50    今日 3/400
```

逐项拆解：

---

### 「今日 3/400」—— 上限被设成了 400

`getDailyLimit()` 读的是 `vocabulary-settings.dailyLimit`，没有自动纠正。某种原因这个值变成了 400：

```javascript
// 当前代码：base 路径缺少上限保护
function getDailyLimit() {
    var base = s.dailyLimit || 20;
    // ...
    return base;   // ← 如果 base=400，就直接返回 400
}
```

**修复**：所有读取路径都 `Math.min(base, 50)`。

但更深层的问题：为什么「新词学了几个」要和「复习了几个」混在一条统计里？新词和复习是两回事。

---

### 「本轮 222/563」—— 两个数都对不上

**222** = `seenCount`，这不是「完成了多少张卡」，而是**总共拿过多少次卡**。

每张卡如果评「不认识」→ 30 秒后回炉再给你 → 又评「不认识」→ 又回炉 → 3 次后放弃（标记 leech）。一张卡产生 3 次 `seenCount` 但 0 次「通过」。

你的情况：
```
50 张困难词 × 每张被拉出 3 次 = 150 次 seenCount
50 张通过 × 每张 1 次 = 50 次
5 张回炉排队中 ≈ 5 次
剩余 ~17 次 = 模糊卡二次拉出
────────────────────────
seenCount ≈ 222  ← 但真正「处理掉了」的只有 ~105 张
```

**563** = `deck.length + delayedQueue` 的混合。`deck` 里包含「已复习但未到期的卡」，它们在 `startNewDeck()` 的 else 分支被误加进去了：

```javascript
} else {
    dueCards.push(w); // 注释写"已被过滤"，代码没过滤！
}
```

---

### 「困难 50」—— 回炉 3 次就放弃

`LEECH_THRESHOLD = 3`。同一张卡本轮 fail 3 次 → 标记 leech → 本轮跳过。这 50 张词是你的**真正薄弱点**，但系统选择直接放弃。

**问题**：今天不管、明天不管，SM-2 会把它排在什么时候？下次看到可能是 1 天后、3 天后、7 天后…但你真正需要的是**每天看一眼**这些硬骨头，直到记住。

---

## 二、根本问题

当前系统是个**精神分裂的杂交体**：

| 身份 | 想做什么 | 实际做的 |
|------|---------|---------|
| SM-2 间隔复习器 | 今天看一次，按算法排到明天/后天… | 但「不认识」的词 30 秒后回炉又看 |
| 即时回炉练习器 | 不认识就立刻再看 | 但看了 3 次还不会就直接放弃 |
| 日上限控制器 | 每天只引入 N 个新词 | 但 `dailyLimit` 可以设 400，没人拦 |

**SM-2 和回炉循环是矛盾的**。SM-2 假设一个词今天看一次就够了，不认识就排明天再看。回炉循环说「不认识就在 30 秒内再看一遍」。这两个逻辑互相打架，导致：

- 一个词被拉到面前 3-6 次（30 秒间隔），靠短期记忆硬记
- `seenCount` 膨胀，进度看起来永远做不完
- 真正需要反复看的硬骨头被标成 leech 丢弃
- 用户不知道今天到底完成了什么

---

## 三、重构方案

### 新会话模型：一卡一次，不认识排明天

```
【旧】                           【新】
┌─────────────────────┐        ┌─────────────────────┐
│ 拿一张卡             │        │ 拿一张卡             │
│ 翻面看答案           │        │ 翻面看答案           │
│ 评分                 │        │ 评分                 │
│   ┌─不认识 → 回炉     │        │   ┌─不认识 → 排明天   │
│   │  (30秒后再来)     │        │   ├─模糊   → 排明天   │
│   │  ...循环3次→放弃  │        │   └─认识   → SM-2   │
│   ├─模糊 → 回炉       │        │                     │
│   │  (2分钟后)        │        │ 下一张（不回炉）      │
│   └─认识 → 通过       │        │                     │
│                     │        │ 每 5 张：不认识卡     │
│ 下一张（主队列/回炉卡）│        │   可选"再看一次"     │
└─────────────────────┘        └─────────────────────┘
```

### 核心改动

**1. 删除回炉队列**
- 不认识/模糊 → SM-2 interval=1（明天再看），**本轮不回炉**
- 每完成 5 张卡，弹一个「刚才 3 张不认识的词，要再看一眼吗？」的快捷回顾——**用户主动选择**，不自动塞

**2. 删除 leech 废弃机制**
- 没有「放弃」这回事。硬骨头就每天看一次，直到记住
- 没有 `LEECH_THRESHOLD`，没有 `delayedQueue`

**3. `seenCount` 改为「已处理/总数」**
- 已处理 = 卡片被取出并完成评分（只看一次）
- 总数 = 初始卡组中不重复的卡片数
- **一卡只看一次，所以 已处理 ÷ 总数 = 真实的进度**

**4. 统计栏重新设计**
```
【旧】本轮 222/563 | 通过50 | 回炉5 | 困难50 | 今日3/400
【新】进度 50/120 | ✓认识 30 | ~模糊 12 | ✗不认识 8 | 📅待复习 +80
```

| 显示 | 含义 |
|------|------|
| 进度 50/120 | 已处理 50 张，总共 120 张 |
| ✓ 认识 30 | 评了「认识」5 分 |
| ~ 模糊 12 | 评了「模糊」3 分（明天会再出现）|
| ✗ 不认识 8 | 评了「不认识」1 分（明天会再出现）|
| 📅 待复习 +80 | 合并：`今天的待复习` = 初始待复习 - 已处理 + 今天新增的不认识/模糊 |

**5. `dailyLimit` 硬上限**
- 所有路径统一 `Math.min(val, 50)`
- 新建一个显示：「🆕 今日新词 3/20」（独立于复习进度）

**6. 修复 `startNewDeck` 的过滤 bug**
- `showDueOnly` 模式下，已复习未到期的卡**真正不加入**
- `applyFilters` 里 `isDue()` 过滤已经做了 → `startNewDeck` 里不再二次过滤

**7. 完成页重新设计**

```
🎉 本轮完成！
120 张卡片全部处理完毕

  认识     模糊     不认识
   30       12        8
  (25%)    (10%)     (7%)

  掌握率  62.5%

  📅 明日预计复习 +28 张
  🆕 今日新词 3/20

  [🔄 再来一轮]  [📋 只看不认识的]
```
