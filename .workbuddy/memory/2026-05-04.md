## 修复11：小组件按钮点击无响应（第二轮）(21:23)

**根因分析：**
1. **跨 iframe `elementFromPoint` 不可靠** — iframe 内部的 3D 变换（`translateZ(15px)`、`perspective`）将按钮推到2D平面之外，`elementFromPoint` 找不到它们
2. **坐标匹配也有问题** — `getBoundingClientRect()` 返回的是变换前的布局坐标，超出 iframe 260px 可视范围后坐标全部错误

**修复方案：postMessage 双向通信**
1. **index.html `forwardTapToIframe()`** — 向 iframe 发送 `WIDGET_TAP` 消息 + 本地坐标
2. **pomodoro.html message handler** — 收到 `WIDGET_TAP` 后，用 `document.elementFromPoint(x, y)` 本地查找并 `.click()`
3. **CSS 禁用 3D 变换** — `body.is-mini-widget .glass-card` 和 `.glass-3d` 添加 `transform: none !important` + `transform-style: flat !important` + 子元素 `transform: none !important`

**修改文件：** index.html L425-460, pomodoro.html CSS (L2276-2282) + message handler (L7439)

## 修复12：小组件按钮点击无响应（第三轮）(21:40)

**根本原因（最终确认）：** `index.html` L353 的 `pointerdown` 事件处理器中调用了 `e.preventDefault()`，这**阻断了整条浏览器事件链**（pointerdown → pointerup → mousedown → mouseup → click），导致后续的 click 事件永远不会生成。之前 Fix 11 中在 `pointerup` 中调用 `forwardTapToIframe` 也不可靠，因为 `setPointerCapture` 也会干扰事件路由。

**修复方案：**

1. **移除 `e.preventDefault()`**（index.html L355）
   - `pointerdown` 不再阻止默认行为，事件链恢复正常

2. **新增 `dragShield.addEventListener('click', ...)`**（index.html L420-430）
   - 使用 click 事件替代 pointerup 来转发点击
   - click 事件最可靠，浏览器原生支持鼠标和触摸
   - 通过 `hasMoved` 标志区分拖拽结束的 click（忽略）和真正点击（转发）

3. **添加全流程调试日志**
   - `index.html`: `[Shield] click forwarded` → `[FWD] parent(X,Y) → iframe(X,Y)` → `[FWD] ✓ matched!`
   - `pomodoro.html`: `[TAP] received WIDGET_TAP` → `[TAP] elementFromPoint →` → `[TAP] ✓ clicking`

**事件流（修复后）：**
```
pointerdown（标记起点，不阻止默认）
  → pointerup（仅处理拖拽结束）
  → click 事件触发！
    → dragShield click handler
    → forwardTapToIframe(e)
      → postMessage WIDGET_TAP 到 iframe
      → 坐标匹配兜底 .click()
    → pomodoro.html 收到 → elementFromPoint → 按钮 click
```

**修改文件：** index.html L353-358, L407-430, L432-478; pomodoro.html L7451-7464
