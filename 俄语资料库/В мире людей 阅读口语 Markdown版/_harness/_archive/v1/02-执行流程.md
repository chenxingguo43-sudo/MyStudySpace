# 02 执行流程

## 标准流程

每个 agent 任务按以下顺序执行：

1. 读取必读文件。
2. 明确本次任务目标。
3. 明确输入文件和输出目录。
4. 检查是否需要修改正式底稿。
5. 如果不需要，所有产物写入派生目录。
6. 执行任务。
7. 生成报告。
8. 如涉及正式底稿或结构数据，运行 validator。
9. 给出下一步建议。

## 任务前检查

开始前必须回答：

- 本次任务属于哪一类：例句匹配 / 翻译 / 卡片 / 质量复核 / 其他？
- 输入材料是什么？
- 输出目录是什么？
- 是否会修改正式底稿？
- 需要哪些验收标准？

## 修改正式底稿的额外流程

只有满足以下条件，才允许修改正式底稿：

1. 发现明确错误。
2. 有页面图像、原始 OCR 或其他可靠依据。
3. 修改范围局部、可解释。
4. 修改后更新质量报告。
5. 修改后运行 validator。

不得因为“看起来更通顺”而改写原文。

## 派生任务流程

例句匹配、翻译、卡片生成默认是派生任务：

1. 只读正式底稿。
2. 将产物写入独立目录。
3. 每条产物保留来源链接或页码。
4. 产物必须可回溯到原文。
5. 不污染正式底稿。

## 中止条件

遇到以下情况应停止并报告：

- 找不到必读文件。
- 输出目录不明确。
- 需要修改正式底稿但没有依据。
- validator 失败。
- 发现大面积 OCR 错误，超出本任务范围。
- 多个 agent 产物发生冲突。
